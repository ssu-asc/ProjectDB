## 프로젝트 개요

본 프로젝트는 메모리 오류가 단순한 프로그램 종료를 넘어 데이터 변조와 제어 흐름 변경으로 이어지는 조건을 분석한다. 스택 버퍼 오버플로를 중심으로 메모리 구조와 함수 호출 원리를 학습하고, 직접 제작한 C 프로그램을 디버깅하여 공격 성립 조건을 확인한다. 또한 보호기법 적용 및 코드 수정 전후를 비교하여 방어 원리와 한계를 정리한다.

## 기대 효과

- 메모리 오류의 발생 원인과 공격으로 이어지는 조건을 이해한다.
- 디버거를 활용한 메모리 및 레지스터 분석 능력을 향상한다.
- 보호기법의 역할을 이해하고 안전한 코드 작성 능력을 기른다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- 문제 풀이 과정에서 접한 공격 기법을 이론적으로 정리하고, 동작 원리를 스스로 설명할 수 있는 역량을 확보한다.
- 같은 메모리 오류라도 손상 위치와 입력 제어 범위에 따라 결과가 달라지는 이유를 분석한다.
- 이론 학습과 실험을 연결하여 향후 ROP 및 힙 취약점 학습에 필요한 기초를 다진다.

## 2. 프로젝트 세부내용

- 프로세스의 코드·데이터·스택·힙 영역과 x86-64 함수 호출 규약을 학습한다.
- 간단한 C 프로그램의 소스코드와 어셈블리를 비교하여 스택 프레임과 반환 주소의 역할을 분석한다.
- 스택 버퍼 오버플로 예제를 제작하고 단순 크래시, 인접 데이터 변조, 반환 주소 변조 사례를 비교한다.
- GDB를 활용하여 입력 전후의 메모리, 레지스터 및 실행 흐름 변화를 관찰한다.
- 입력으로 제어할 수 있는 범위, 손상된 값의 사용 시점, 주소 정보가 공격 성립에 미치는 영향을 분석한다.
- Canary, NX, PIE 및 ASLR의 역할을 정리하고 보호 설정에 따른 실험 결과를 비교한다.
- 입력 길이 검사 등으로 취약점을 수정하고 기존 공격 입력과 정상 입력으로 재검증한다.
- 실험 조건, 관찰 결과, 메모리 구조도 및 분석 내용을 최종 보고서로 정리한다.

## 3. 프로젝트 기대효과

- 메모리 손상과 제어 흐름 변경 사이의 관계를 설명할 수 있다.
- 소스코드, 어셈블리 및 메모리 상태를 연결하여 분석하는 능력을 확보한다.
- 공격 실패 원인을 실행 환경과 보호기법 관점에서 구분할 수 있다.
- 재현 가능한 예제와 분석 보고서를 향후 Pwn 학습 자료로 활용할 수 있다.

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- 어셈블리와 호출 규약에 대한 이해가 부족할 수 있으므로 작은 예제부터 단계적으로 분석한다.
- 컴파일러 버전과 최적화 설정에 따라 메모리 배치가 달라질 수 있으므로 환경과 빌드 옵션을 기록한다.
- 단순 크래시를 공격 성공으로 오인하지 않도록 데이터 변조와 제어 흐름 변경을 구분하여 검증한다.
- 학습 범위 확대에 따른 일정 지연을 방지하기 위해 스택 버퍼 오버플로를 중심으로 진행한다.

## 5. 프로젝트 수행시 요구사항 (개발환경, 사전지식 등)

- 개발환경: x86-64 Linux 환경을 갖춘 개인 PC 또는 가상머신
- 개발 및 분석 도구: GCC, GDB, Python 3, pwntools, Git
- 사전지식: C 언어의 배열·포인터·함수, Linux 기본 명령어, Python 기초
- 추가 학습 내용: x86-64 어셈블리, 함수 호출 규약, 메모리 보호기법
- 실험 대상: 직접 제작한 프로그램을 사용하고 실행 환경 및 빌드 설정을 관리한다.

## 개인 수행 계획

- **주요 수행 항목:** 1~2주 차에는 메모리 구조와 함수 호출 원리를 학습한다. 3~4주 차에는 예제 제작과 디버깅을 수행한다. 5~6주 차에는 공격 성립 조건과 보호기법별 결과를 비교한다. 7주 차에는 취약점을 수정하고 재검증하며, 8주 차에는 최종 보고서와 발표 자료를 작성한다.
- **예상 산출물:** C 예제 프로그램 3개 내외, 재현용 Python 스크립트, 보호기법 및 패치 전후 비교표, 메모리 구조도와 디버깅 기록을 포함한 최종 보고서
- **검증 방법:** GDB로 메모리와 실행 흐름 변화를 확인하고 크래시·데이터 변조·지정 함수 실행을 구분한다. 같은 환경에서 반복 실행하여 재현 여부를 확인하며, 패치 이후 기존 공격 입력에 의한 메모리 손상이 발생하지 않고 정상 기능이 유지되는지 검증한다.
