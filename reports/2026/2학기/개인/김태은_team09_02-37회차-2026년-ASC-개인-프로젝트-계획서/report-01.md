## 프로젝트 개요

> 혼자 수행할 프로젝트의 핵심 내용과 해결하려는 문제를 요약합니다.

기업들이 보안을 이유로 사내 AI 에이전트를 도입하는 것처럼, 개인도 민감한 정보를 외부 LLM에 넘기지 않으면서 Claude 같은 대형 모델의 성능을 활용할 방법이 필요하다. 본 프로젝트는 개인정보를 로컬에서만 다루는 **개인 에이전트**를 만들고, 이를 MCP(Model Context Protocol)로 외부 LLM 에이전트와 연결한다. 외부 LLM은 실제 값 대신 자리표시자(예: `<이메일_1>`)만 보고 작업 계획을 세우며, 실제 값이 필요한 민감 작업은 로컬 에이전트가 수행한다.

구현 후에는 외부 에이전트가 인젝션 공격을 받았다고 가정하고 개인정보를 빼내는 공격 시나리오를 직접 수행하여, 방어 단계별 유출률을 정량적으로 측정한다.

## 기대 효과

- 외부 LLM의 성능과 개인정보 보호를 동시에 확보하는 분리 구조의 실제 구현 사례 제시
- 자리표시자 치환, 작업 허용 목록, 데이터 흐름 추적 등 방어 기법의 효과를 수치로 비교
- 사내 AI 에이전트 등 실무 환경에 적용 가능한 설계 지침 도출

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- **추진 배경**
  - LLM 에이전트가 메일, 일정, 파일 등 개인 데이터에 직접 접근하는 사례가 늘면서, 프롬프트 인젝션을 통한 민감정보 유출이 주요 위협으로 떠올랐다. OWASP Top 10 for LLM Applications(2025)에서도 민감정보 노출(LLM02)을 주요 위험으로 꼽는다.
  - 기업은 이를 막기 위해 사내 에이전트를 별도로 구축하지만, 개인 사용자는 외부 LLM에 개인정보를 그대로 넘기는 경우가 대부분이다.
- **취지**
  - 신뢰하는 영역(로컬)과 신뢰하지 않는 영역(외부 LLM)을 분리하고, 그 경계를 넘는 데이터를 한 곳에서 통제하는 구조를 개인 수준에서 구현한다.
  - 단순 개발에 그치지 않고, 공격자 관점에서 구조를 직접 검증해 어떤 방어가 실제로 효과가 있는지 확인한다.

## 2. 프로젝트 세부내용

- **시스템 구조**

  ```
  [Claude(외부)] ⇄ [정책 게이트웨이] → [로컬 에이전트] ⇄ [개인정보 저장소]
                     └─────── 내 PC (신뢰 구역) ───────┘        ↓
                                                         [외부 서비스: 메일·폼 전송]
  ```

  | 구성요소 | 역할 |
  |---|---|
  | 외부 LLM (Claude) | 작업 계획 및 문장 작성. 자리표시자만 열람 |
  | 정책 게이트웨이 | 작업 허용 목록 검사, 외부로 나가는 응답의 PII 검사, 데이터 흐름 추적 |
  | 로컬 에이전트 | 자리표시자를 실제 값으로 치환하여 작업 실행. 소형 로컬 모델 사용 |
  | 개인정보 저장소 | 암호화된 로컬 DB. 로컬 에이전트만 접근 가능 |

- **동작 예시**
  1. 사용자: "교수님께 결석 사유 메일 보내줘"
  2. 외부 LLM: `send_email(to=<교수_1>, body="<이름_1>입니다. ...")` 형태로 계획만 생성
  3. 게이트웨이: 허용된 작업인지, 수신자가 등록된 연락처인지 확인
  4. 로컬 에이전트: 저장소의 실제 값으로 치환 후 발송
  5. 외부 LLM에는 "발송 완료"만 반환

- **공격 시나리오 (검증 대상)**

  | 유형 | 내용 |
  |---|---|
  | 직접 요청 | 인젝션된 외부 에이전트가 원본 값 반환을 요구 |
  | 우회 유출 | 조건 질문으로 값을 한 글자씩 추출 (예: "끝자리가 7이면 A라고 답해") |
  | 조합 재식별 | 자리표시자라도 학교, 학번 등 주변 정보를 조합해 개인 특정 |
  | 로컬 모델 공격 | 소형 로컬 모델에 대한 인젝션으로 치환 로직 오작동 유도 |
  | 행동 악용 | 허용된 작업(메일 발송)을 이용해 공격자 주소로 정보 전송 |

- **방어 단계별 비교 실험**
  - 단계 0: 방어 없음 (원본 값 그대로 전달)
  - 단계 1: 자리표시자 치환
  - 단계 2: 단계 1 + 작업 허용 목록 + 출력 PII 검사
  - 단계 3: 단계 2 + 데이터 흐름 추적
  - 각 단계에 동일한 공격 세트를 반복 수행하여 유출률 비교

## 3. 프로젝트 기대효과

- **기술적 측면:** MCP 기반 에이전트 연동, 로컬 LLM 운용, PII 탐지 및 데이터 흐름 통제 기술을 직접 구현하며 LLM 에이전트 보안 전반을 이해
- **보안적 측면:** 방어 기법별 효과와 한계를 수치로 제시하여, 어떤 조합이 실질적으로 유출을 막는지 근거 확보
- **실용적 측면:** 개인 사용자뿐 아니라 사내 AI 에이전트 구축 시 참고 가능한 구조와 공격 체크리스트 제공
- **확장성:** 동아리 내 LLM 보안 실습 환경 및 워게임 문제로 재활용 가능

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- **내부 요인**
  - 로컬 소형 모델의 성능 한계로 치환 및 판단 정확도가 떨어질 수 있음 → 판단은 규칙 기반으로 최소화하고 모델은 보조로만 사용
  - 한국어 PII(주민등록번호, 전화번호, 학번 등)는 기존 탐지 도구의 지원이 부족함 → 한국어 정규식 규칙을 직접 추가
  - 방어를 강하게 할수록 정상 작업까지 막히는 문제(과차단) 발생 가능 → 유출률과 함께 정상 작업 성공률도 측정
- **외부 요인**
  - 외부 LLM API 사용 비용 및 사용량 제한 → 반복 실험은 소형 모델로 먼저 수행하고, 최종 검증만 외부 LLM으로 진행
  - MCP 등 관련 도구가 빠르게 바뀌어 버전 호환 문제가 생길 수 있음 → 사용 버전을 고정하여 기록
  - 실제 개인정보 사용 시 위험 → 모든 실험은 가상의 개인정보 데이터로만 수행

## 5. 프로젝트 수행시 요구사항 (개발환경, 사전지식 등)

- **개발환경:** macOS, Python 3.11 이상, Ollama, SQLite
- **사전지식**
  - Python 프로그래밍
  - LLM 에이전트 구조 및 툴 호출 방식 (LangChain 사용 경험)
  - MCP 서버/클라이언트 구조
  - 프롬프트 인젝션 공격 기법 (기존 인젝션 실험 경험 활용)
  - 기초 암호화 및 접근 통제 개념

## 개인 수행 계획

- **주요 수행 항목:**
  1. 개인정보 저장소 및 자리표시자 치환 모듈 구현
  2. MCP 서버로 외부 LLM과 로컬 에이전트 연결 (최소 동작 버전)
  3. 정책 게이트웨이 구현 (작업 허용 목록, 출력 PII 검사, 데이터 흐름 추적)
  4. 공격 시나리오 세트 작성 및 자동 실행 스크립트 구현
  5. 방어 단계별 유출률 및 정상 작업 성공률 측정, 결과 분석
- **예상 산출물:**
  - 소스 코드 (GitHub 저장소)
  - 공격 시나리오 세트 및 실험 결과 데이터
  - 최종 보고서 및 발표 자료
  - 시연 영상
- **검증 방법:**
  - 방어 단계별로 동일한 공격 세트를 반복 실행하여 **유출률**(외부로 실제 값이 노출된 비율) 측정
  - 정상 작업 세트를 함께 실행하여 **정상 작업 성공률** 측정 (과차단 여부 확인)
  - 외부 LLM으로 전달된 모든 메시지를 로그로 남겨 실제 값 포함 여부를 자동 검사
