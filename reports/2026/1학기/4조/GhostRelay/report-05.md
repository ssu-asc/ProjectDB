## 이번 회차 상세 진행 내용

### 1. 회의 목적

이번 회차에는 새로운 기능 구현을 진행하지 않고, 팀 회의를 통해 **8월 발표까지의 남은 작업과 담당**을 정리하였다.

4차 보고서까지 Agent, Backend, Dashboard, 공격 시나리오의 역할과 전체 파이프라인 검증 방향은 이미 정리되어 있다. 다만 발표일까지 무엇을 우선할지, 누가 어떤 산출물을 만들지 더 구체적으로 나눌 필요가 있었다.

회의에서 합의한 우선순위는 다음과 같다.

```text
1. 벤치마크 (실제 비교 검증)
2. 프론트엔드·데모 flow 완성
3. 발표자료 초안 준비
```

이 세 가지가 갖춰진 뒤, 박도현·강수빈이 8월 발표 리허설과 발표 구성을 이어가기로 하였다.

---

### 2. 8월 발표 대비 작업 분담

| 담당 | 작업 | 목표 |
|------|------|------|
| 박도현 | 벤치마크 (실제 비교) | 탐지 성능·비교 근거를 수치/표로 정리해 발표 설득력 확보 |
| 이정훈 · 장수연 | 프론트 및 데모 완성도 준비 (flow 완성) | Agent → Backend → Dashboard 시연 흐름이 끊기지 않도록 완성 |
| 이정훈 · 장수연 | 발표자료 초안 준비 | 아키텍처·데모 순서·핵심 화면이 담긴 발표 자료 초안 작성 |
| 박도현 · 강수빈 | 8월 발표 준비 (후속) | 프론트·데모·발표자료가 준비된 뒤 발표 구성·리허설 진행 |

역할 흐름은 다음과 같다.

```text
이정훈 · 장수연
  → 데모 flow 완성 + 발표자료 초안
        ↓
박도현
  → 벤치마크(실제 비교) 병행
        ↓
박도현 · 강수빈
  → 8월 발표 준비·리허설
```

---

### 3. 벤치마크 방향

박도현이 담당할 벤치마크는 “기능이 동작한다”는 수준을 넘어, **실제 비교**를 통해 프로젝트의 탐지·대응 의미를 설명하기 위한 자료로 준비하기로 하였다.

비교·정리에 포함할 후보 항목은 다음과 같다.

| 항목 | 목적 |
|------|------|
| 시나리오별 탐지 여부 | 기대 룰과 실제 발화 결과 대조 |
| 대시보드 반영 여부 | Agent 탐지가 웹까지 이어지는지 확인 |
| 오탐·미탐 기록 | 한계와 개선 여지를 솔직히 제시 |
| (가능 시) 유사 도구·베이스라인 대비 | 발표에서 “왜 이 설계인가”를 비교로 설명 |

세부 비교 대상과 측정 방법은 다음 회차에서 구체화한다.

---

### 4. 프론트·데모 flow 완성

이정훈·장수연이 담당할 핵심은 4차에서 논의한 개선 항목을 나열하는 것이 아니라, **발표 시연이 한 번에 이어지는 flow**를 만드는 것이다.

목표 flow는 다음과 같다.

```text
공격/시나리오 실행
  → EDR Agent 이벤트 생성
  → 백엔드 수집·저장
  → 대시보드에서 alert/이벤트 확인
```

이를 위해 백엔드 API 안정화와 프론트엔드 화면(목록·요약·상세 등)의 완성도를 함께 맞추기로 하였다. 세부 UI 개선(필터, summary 카드 등)은 flow가 끊기지 않는 범위를 우선한다.

---

### 5. 발표자료 및 8월 준비 일정

발표자료 초안은 이정훈·장수연이 먼저 만들고, 이후 박도현·강수빈이 발표 스크립트·시연 순서·질의 대응을 준비하는 2단 구조로 합의하였다.

| 단계 | 담당 | 내용 |
|------|------|------|
| 1단계 | 이정훈 · 장수연 | 발표자료 초안, 데모 화면·flow 정리 |
| 2단계 | 박도현 · 강수빈 | 발표 구성, 벤치마크·시나리오 설명, 리허설 |

이번 회차에서는 위 일정과 담당만 확정하였으며, 실제 슬라이드·벤치마크 표·데모 스크립트는 다음 회차 산출물로 남긴다.

## 이슈 및 해결 방안

| 이슈 | 해결 방법 |
|------|----------|
| 이번 회차는 구현 산출물이 없어 진행률이 정체되어 보임 | 8월 발표 전 필수 작업을 3개로 압축하고 담당을 확정해 다음 회차 실행 속도를 높임 |
| 발표 준비가 여러 사람에게 분산되면 책임 경계가 모호해질 수 있음 | 데모·발표자료(정훈·수연) / 벤치마크(도현) / 발표 리허설(도현·수빈)으로 단계를 분리 |
| 벤치마크 비교 대상이 아직 구체적이지 않음 | 다음 회차에서 측정 항목·비교 기준을 먼저 확정한 뒤 표를 작성 |
| 프론트 개선 항목이 많아 발표 전 모두 구현하기 어려울 수 있음 | flow 완성을 우선하고, 부가 UI는 시간 여유에 따라 선택 적용 |
