## 프로젝트 개요

> 혼자 수행할 프로젝트의 핵심 내용과 해결하려는 문제를 요약합니다.

LLM은 안전 정렬(safety alignment)로 유해 요청을 거부하도록 학습되지만, 입력을 번역·인코딩하거나 자동으로 다듬은 프롬프트로 이를 우회할 수 있다는 연구가 다수 보고되어 있다. 그러나 이런 논문은 상용 API나 대형 GPU를 전제로 하는 경우가 많아, 개인이 비용 부담 없이 재현하고 결론을 확인하기 어렵다.

본 프로젝트는 서로 다른 공격 계열을 대표하는 **논문 3편**을 후보로 두고, 스모크 테스트와 점수화로 주 재현 대상을 확정한다. 후보는 ① Multilingual Jailbreak(Deng et al., ICLR 2024, 번역 기반), ② Jailbroken(Wei et al., NeurIPS 2023, 템플릿·인코딩 기반), ③ PAIR(Chao et al., 2023, 자동 생성 기반)이다. ①②는 무료이며, ③은 공격용 LLM에만 소액 API를 쓰는 **조건부 후보**(상한 약 10~20달러)이다. 공통 평가 환경(Ollama 로컬 모델 + Llama Guard 계열 판정기)을 먼저 만들고 논문별 공격을 모듈로 얹어, **"소형 오픈 모델의 안전성은 언어·공격 유형·자동/수동 공격에 따라 어떻게 달라지는가"** 라는 결론을 낸다. 전체 실험은 Docker로 패키징해 GitHub에 공개한다.

## 기대 효과

- 논문별 핵심 주장을 소형 오픈 모델에서 직접 검증하고, 원 논문과의 차이를 분석한다.
- 언어별(한국어 포함), 공격 유형별, 자동/수동 공격별 ASR(공격 성공률) 표라는 명확한 결과물을 얻는다.
- 경량 방어의 효과와 부작용(정상 질문 오거부)을 함께 확인한다.
- 무료·로컬·Docker로 재현되는 평가 환경을 남겨, 다른 학생이 그대로 실행하고 확장할 수 있다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- LLM 서비스가 확산되면서 안전장치 우회(탈옥) 문제가 실제 위협으로 다뤄지고 있으나, 한국어 환경과 소형 로컬 모델에 대한 검증 사례는 적다.
- 탈옥 논문의 상당수는 유료 API(GPT-4 등)나 GPU 서버를 전제로 해서 개인이 재현하기 어렵다.
- 본 프로젝트는 **로컬 재현 가능성, 비용, 결론 도출 가능성**을 기준으로 후보를 3편으로 좁혀, 2027년 2월 중순 마감까지 혼자서 끝까지 수행할 수 있는 범위로 설계한다.
- 연구·방어 목적에 한정하며, 유해 응답 원문은 저장소에 공개하지 않고 집계 통계만 공개한다.

## 2. 프로젝트 세부내용

### 2.1 후보 논문 3편과 선정 기준

**후보 3편** (①②는 무료, ③은 소액 API 예산을 전제로 한 조건부 후보)

| | ① Multilingual Jailbreak | ② Jailbroken | ③ PAIR  |
|---|---|---|---|
| 논문 | Deng et al., ICLR 2024 (arXiv:2310.06474) | Wei et al., NeurIPS 2023 (arXiv:2307.02483) | Chao et al., 2023 (arXiv:2310.08419) |
| 공격 계열 | 번역 | 템플릿·인코딩 | 자동 생성 |
| 공격 방식 | 유해 질문을 다른 언어로 번역해 입력 | 인코딩(Base64 등), prefix 주입, 거부 억제 등 | 공격용 LLM이 타깃의 응답을 보고 프롬프트를 최대 20회 반복 개선 |
| 공개 자료 | MultiJail 데이터(영어 315문항 × 9개 언어, **한국어 포함**), MIT | 공식 레포 미확인 → 공격을 직접 구현 | 공식 레포(MIT). API 키·WandB 전제라 호출부 수정 필요 |
| 비용 | 0원 (API 불필요) | 0원 | 공격용 LLM만 저렴한 API 모델 사용, 상한 10~20달러 (타깃·판정은 로컬) |
| 로컬 실행 | Ollama로 입력만 하면 됨 | Ollama + 변환 스크립트 | 타깃은 Ollama, 공격용 LLM은 API |
| 도출 가능한 결론 | 언어별 ASR 차이, 한국어의 위치 | 공격 유형별 ASR 순위 | 자동 공격 대 수동 공격(①②)의 성공률·질의 수 비교 |
| 주요 위험 | 소형 모델의 한국어 응답 품질이 낮음 | 소형 모델이 인코딩을 못 읽어 "무효 응답"이 많을 수 있음 | API 약관상 거부·계정 제한 가능, 비용 초과, 호출부 수정 부담 |

**확정 절차:** 11월 둘째주까지 각 논문의 스모크 테스트(최소 예제 실행, 반나절씩)를 수행하고 점수를 갱신한다. 최고점 논문을 **주 재현 대상**으로 확정하고, 테스트를 통과한 나머지를 **비교 확장**으로 추가한다. 테스트에 실패한 후보는 제외하고 사유를 기록한다.

### 2.2 연구 질문 (논문별 결론의 형태)

- RQ1 (Multilingual). 소형 오픈 모델에서도 "저자원 언어일수록 ASR이 높다"는 경향이 재현되는가? 한국어는 영어 대비 어떠한가?
- RQ2 (Jailbroken). 인코딩·prefix 주입·거부 억제 중 어떤 공격 유형이 가장 효과적인가? 소형 모델에서는 "무효 응답"이 얼마나 나오는가?
- RQ3 (PAIR). 자동 생성 공격은 수동 공격(①②) 대비 성공률과 필요한 질의 수에서 어떠한가?
- RQ4 (방어). 경량 방어는 ASR을 얼마나 낮추고, 정상 질문 응답을 얼마나 해치는가?

### 2.3 수행 내용

1. **공통 평가 환경 구축:** 모델 호출(Ollama API), 응답 판정(Llama Guard 계열), 결과 저장(CSV), 집계·그래프 모듈을 먼저 만든다. 논문별 공격은 이 환경에 모듈로 추가한다.
2. **스모크 테스트와 확정:** 2.1의 절차대로 진행한다.
3. **재현:** 주 재현 논문의 공격을 모델 2개에서 실행해 ASR을 측정하고, 원 논문의 보고 경향과 비교한다.
4. **비교 확장:** 통과한 나머지 논문을 같은 환경에서 실행해 결과를 한 표로 비교한다.
5. **방어 추가:** (a) 안전 시스템 프롬프트, (b) Llama Guard 입력 필터. 방어 전·후 ASR과 정상 질문셋 오거부율을 측정한다.
6. **판정 신뢰도 점검:** 표본 약 50개를 직접 확인해 판정기와의 일치율을 보고한다. 원 논문과 판정 방식이 다를 수 있음을 한계로 명시한다.
7. **패키징:** Docker, README, LICENSE, 사용 OSS·AI 도구 출처 표를 정리한다.

### 2.4 로컬(M3 Pro) 실행 설계

- **모델:** Ollama의 Llama 3.2 3B, Qwen2.5 7B(4bit 양자화)를 기본으로 하고, 메모리가 허락하면 Gemma 2 9B를 추가한다. (메모리 용량 확인 후 확정)
- **Docker 구성:** macOS의 Docker 컨테이너는 GPU(Metal)를 쓸 수 없으므로 Ollama는 맥 호스트에서 실행하고, 실험·분석 코드는 컨테이너에서 호스트의 Ollama API(`host.docker.internal`)를 호출한다.
- **비용:** ①②는 유료 API를 쓰지 않는다(0원). ③ PAIR를 편입하면 공격용 LLM 호출 비용만 발생하며 상한은 약 10~20달러로 두고, API 대시보드에 월 사용 한도를 설정한다. (예상 비용은 추정치이므로 실행 전 현재 요금표로 재계산한다.)
- **규모 조절:** 응답이 느리면 문항 수·언어 수·행동 수를 줄여 단계적으로 확대한다.

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- **내부 요인**
  - 혼자 수행하므로 판정기 검증, Docker 정리, 문서화가 막판에 몰릴 수 있다. → 공통 환경을 먼저 만들고 월별 목표를 둔다. 마감 2주 전부터는 새 기능 없이 정리만 한다.
  - 후보를 모두 하려다 범위가 커질 수 있다.
- **외부 요인**
  - 소형 모델은 안전 정렬이 약하고 한국어·인코딩 이해가 낮아 논문 수치와 다를 수 있다. → 차이 자체를 결과로 기록하고 "무효 응답" 분류를 도입한다.
  - 판정 방식 차이로 ASR 수치가 달라질 수 있다. → 표본 대조 결과를 보고하고 한계를 명시한다.
  - ③ PAIR 사용 시 API 이용 정책 위반(안전장치 우회 시도 금지 조항), 계정 경고·제한, 비용 초과 가능성. → 사용 전 제공사 이용 정책을 확인하고, 문제 소지가 있으면 ③을 제외한다. 월 사용 한도를 설정한다.
  - 로컬 추론 속도·메모리 제한. → 양자화 모델, 문항 수 조절, 필요 시 Colab 보조.
  - 데이터·모델 라이선스. → 사용 전 라이선스를 확인하고 README에 표로 정리한다. Llama 계열은 Meta 라이선스 약관을 확인한다.
  - 윤리 문제: 유해 요청과 탈옥 프롬프트를 다룬다. → 연구·방어 목적을 명시하고 응답 원문과 탈옥 프롬프트 모음은 저장소에 올리지 않으며 집계 통계만 공개한다.

  - 정상 질문셋으로 방어 적용 후 오거부율을 측정한다.
  - 깨끗한 환경에서 README대로 실행해 재현되는지 확인한다.
