### 2. 취약점 점검 시나리오 설계

각 영역별로 FindTheGap 프로그램 규정(자동화 금지, 실제 유저 계정 테스트 금지 등)을 준수하는 수동 점검 시나리오를 설계하였다.

모든 점검은 프로그램에서 허용한 도메인과 본인 소유 테스트 계정에 한정하여 수행하며, 실제 사용자 정보 접근, 실결제·실충전, 자동화 스캔, 대량 요청, 서비스 장애를 유발할 수 있는 행위는 수행하지 않는다.

#### 영역 1: 인증 (담당: 김시현, 곽범준)

| 시나리오 ID | 내용 | 점검 방법 | 예상 심각도 |
| --- | --- | --- | --- |
| A-1 | **비밀번호 재설정 토큰 분석** — 재설정 링크 토큰의 예측 가능성 및 만료 없는 재사용 가능 여부 확인 | 재설정 요청 후 Burp로 토큰 구조 분석 | High |
| A-2 | **세션 토큰 분석** — 로그인 후 발급된 쿠키/JWT의 알고리즘, 만료 시간, 예측 가능성 분석 | Burp Decoder로 토큰 구조 분석 | Medium |
| A-3 | **QR 로그인 플로우 분석** — QR 인증 요청-응답 과정에서 토큰 재사용 또는 세션 고정 가능 여부 | qr.plaync.com 플로우를 Burp로 캡처 후 분석 | High |
| A-4 | **OAuth state 파라미터 미검증** — 3rd party 로그인(thirdparty.plaync.com)에서 state 값 검증 생략 시 CSRF로 계정 연동 가능 여부 | 로그인 요청에서 state 파라미터 제거/변조 | Medium |
| A-5 | **IDOR — 본인 소유 테스트 계정 간 접근 제어 검증** — id.plaync.com에서 user_id 등 계정 식별자를 변조해 테스트 계정 간 접근 제어가 정상 적용되는지 확인 | Burp Repeater로 파라미터 변조 | High |

#### 영역 2: 결제/월렛 (담당: 이예빈)

| 시나리오 ID | 내용 | 점검 방법 | 예상 심각도 |
| --- | --- | --- | --- |
| P-1 | **결제 금액 파라미터 변조** — 주문 요청의 price/amount 값을 변조해 서버 측 검증 여부 확인 | Burp Intercept → price 값 변조 후 전송 | Critical |
| P-2 | **IDOR — 테스트 계정 A/B 간 주문 리소스 접근 제어 검증** — order_id, payment_id를 변조해 테스트 계정 간 주문 리소스 접근 제어가 정상 적용되는지 확인 | Burp Repeater로 ID 값 증감 변조 | High |
| P-3 | **트랜잭션 재전송 공격** — 완료된 결제 요청을 재전송했을 때 중복 처리 여부 확인 | Burp Repeater로 동일 요청 재전송 | High |
| P-4 | **충전 응답 값 변조** — 코인 충전 완료 응답의 코인 수량 값을 변조했을 때 서버 반영 여부 확인 | Burp Intercept → 응답 변조 | Critical |

#### 영역 3: API (담당: 곽범준, 류태현)

| 시나리오 ID | 내용 | 점검 방법 | 예상 심각도 |
| --- | --- | --- | --- |
| B-1 | **IDOR — API 파라미터 변조** — store-bff.plaync.com API 요청의 user_id, item_id를 변조해 테스트 계정 간 접근 제어가 정상 적용되는지 확인 | Burp Repeater로 ID 값 변조 | High |
| B-2 | **인증 토큰 없이 API 접근** — Authorization 헤더 제거 시 인가 우회 여부 확인 | Burp Repeater → Authorization 헤더 제거 | High |
| B-3 | **HTTP 메서드 변조** — GET 전용 엔드포인트에 PUT/DELETE 요청 전송 시 서버 동작 확인 | Burp Repeater → 메서드 변경 | Medium |
| B-4 | **권한 상승 시도** — ncid.plaync.com에서 일반 사용자 토큰으로 관리자 기능 엔드포인트 접근 시도 | API 엔드포인트 열거 후 접근 시도 | High |

## 이슈 및 해결 방안

- **문제 상황:** 팀원 간 보안 배경 차이로 인해 점검 영역 균등 배분이 어려웠다.
- **해결 현황:** 역량에 따라 점검 난이도 기준으로 영역을 배분하고, 보안 지식이 상대적으로 부족한 팀원은 기초 시나리오 수행에 집중하는 방식으로 역할을 조정하였다.
