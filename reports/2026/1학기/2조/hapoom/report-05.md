# [제 5차 프로젝트 진행 보고서] 하품 홈페이지 웹 서비스 보안 취약점 분석

- **팀원:** (팀장) 20245035_강준수, (팀원) 20245039_김레빈, 20251790_김준수, 20252751_김홍균
- **활동 기간:** 2026. 07. 15. ~ 2026. 07. 21. (1주)

## 팀 전체 진행 현황

- **이번 회차 목표:**
  4차 보고서에서 로컬 PoC로 확인한 취약점을 실제 코드 수정안으로 전환하고, 패치끼리 충돌하거나 기존 기능을 깨뜨리는 지점이 없는지 로컬 분석 랩에서 검증한다. 운영 중인 `https://hapum.org/` 서비스에는 패치를 적용하지 않고, 공격성 테스트도 진행하지 않는다.

- **현재 진행률:** 95%
  코드 수준 취약점과 패치 상충 문제는 로컬 검증 기준으로 조치 완료. 남은 작업은 운영 배포 전 환경변수 설정, 자격 증명 회전, DB migration, 실제 프록시/TLS/메일/스토리지 환경에서의 배포 후 재검증이다.

- **주요 달성 사항:**
  - MySQL, Redis, Spring Boot 기반 로컬 분석 랩 구성
  - IDOR, CSRF, 파일 업로드, 저장형 XSS 패치 적용
  - 인증, 세션, Rate Limit, 접근 제어 강화
  - 설정 파일의 Secret 환경변수 분리
  - CORS, CSP, 보안 헤더, 신뢰 프록시 정책 강화
  - 관리자 작업 감사 로그 추가
  - 공개 문서 및 개인정보 노출 경로 차단
  - 외부 CDN 자산을 로컬 고정 버전으로 교체
  - 반복 실행과 초기화가 가능한 로컬 검증 환경 정리

## 이슈 및 해결 방안

- **문제 상황:**
  1. 여러 보안 패치가 같은 컨트롤러, 설정 파일, 템플릿, 리소스 경로를 동시에 건드려 충돌 가능성이 있었다.
  2. CSRF, CSP, 세션 보안, 업로드 경로 정책은 단독 적용보다 조합 적용 시 기능 깨짐 가능성이 컸다.
  3. 운영 환경에는 실제 프록시, TLS, 메일, 스토리지, DB migration이 연결되어 있어 로컬 검증 결과만으로 바로 배포 판단을 내리기 어렵다.
  4. 기존 소스와 산출물에 포함된 민감정보는 코드 패치와 별개로 운영 자격 증명 회전이 필요하다.

- **해결 현황:**
  패치 7개를 깨끗한 원본 소스에 다시 적용해 충돌 여부를 확인. 적용 실패와 코드/리소스 유실은 0건. 자동 테스트 95개, GET 라우트 45개, CSRF 없는 POST 64개, 정적 자산 81개, CSP 응답 44개 검사 통과. 운영 서버는 변경하지 않았고, 배포 전 조치 항목은 별도로 분리.
