# [제 1차 개인 프로젝트 진행 보고서] ASC 개인 프로젝트 1회차

- **작성자:** 배준성 (team02_01)
- **활동 기간:** 2026. 10. 26. ~ 2026. 11. 01.

## 프로젝트 진행 현황

- **이번 회차 목표:** 사용자가 분야와 난이도를 선택하면 새로운 CTF 문제를 생성하는 GUI 기반 초기 프로토타입을 구현하고, 코덱스 및 데이브레이크 모델과 연동한다.
- **현재 진행률:** 20% (전체 일정 대비)
- **주요 달성 사항:** 웹·시스템 해킹·암호학 분야와 난이도 선택 기능, 코덱스 기반 동적 문제 생성, 데이브레이크 모델 선택, 실시간 생성 과정 표시, 참가자용·배포용·운영자용 파일 분리를 구현했다.

## 계획 변경

- **이전 계획:** LLM이 취약 웹을 생성하면 레드팀 에이전트가 공격하고, 확인된 취약점을 코드 라인에 연결한 뒤 패치와 재검증까지 수행하는 웹 중심 구조였다.
- **변경된 계획:** 웹에 한정하지 않고 웹·시스템 해킹·암호학 CTF를 생성하며, Docker 검수 후 정답과 해설에 접근할 수 없는 독립 풀이 에이전트가 문제를 풀도록 범위를 확장했다. 이후 독립 채점기가 플래그, 성공 여부, 소요 시간, 시도 횟수를 판정하고 LLM이 실제 풀이 과정과 출제 의도를 비교해 최종 해설을 작성한다.

## 수행 내역

- **수행 작업:** Python Tkinter 기반 GUI를 제작하고, 로컬 코덱스 명령줄 도구의 ChatGPT 로그인 정보를 재사용해 별도 API 키 없이 문제를 생성하도록 연동했다. 고정 템플릿 반복 문제를 줄이기 위해 무작위 변형 시드와 ‘문제 설계 → 문제 파일 생성 → 구조 검증 및 저장’의 단계별 생성 방식을 적용했다. GPT-5.6 Sol, GPT-6 Sol, GPT-6.1 Sol, GPT-6 Astra 등 데이브레이크 지원 모델을 선택할 수 있도록 구성했으며, 모델별 사이버 접근 프로그램을 자동 지정한다. 생성 결과는 `public`, `deploy`, `private` 폴더로 분리하고 플래그와 공식 풀이는 `private`에만 저장한다. 또한 계획 변경 전 사전 검증으로 Docker에서 DVWA를 실행하고, 로컬 LLM과 HTTP MCP를 연결해 SQL Injection을 재현했다. 정상 입력은 사용자 1명, 테스트 입력은 사용자 5명이 조회되는 응답 차이를 확인해 실제 HTTP 요청 기반 취약점 판정 흐름을 검증했으며, 이 경험을 향후 독립 풀이 에이전트의 도구 호출·응답 비교·과정 기록 구조에 반영하기로 했다.

- **검증/확인 내용:** 웹·시스템 해킹·암호학과 세 가지 난이도의 총 9개 조합 생성, 안전하지 않은 상대 경로 차단, 동일 폴더 덮어쓰기 방지, 자동 폴더명 생성, 한글 진행 메시지를 단위 테스트로 확인했다. 실제 GPT-5.6 Sol·데이브레이크 블루 호출을 통해 한글 설계안과 문제 파일 생성도 확인했다.

## 이슈 및 해결 방안

- **문제 상황:** 사용자는 문제가 생성되는 과정에서 코덱스의 중간 진행 상황을 볼 수 없는 문제가 있었다.
- **해결 현황:** AI 생성을 문제 설계와 파일 생성의 두 단계로 분리해 제목·이야기·핵심 개념·풀이 단계·파일 계획을 중간 결과로 표시하며, 응답 대기 중에는 30초마다 경과 시간을 출력한다.


## 다음 회차 목표

- 최근 보안 이슈 수집·교차 검증·CTF 문제화 포인트 추출을 위한 리서치 입력 구조 설계
- 생성된 서비스형 문제를 Docker로 자동 빌드·실행하고 정상 응답과 플래그 획득 가능성을 검사하는 검수 모듈 구현
- 정답과 공식 풀이에 접근할 수 없는 독립 풀이 에이전트 실행 환경 설계
- 풀이 시간, 시도 횟수, 제출 플래그를 기록하는 독립 채점기 기본 구조 구현
- 분야별 생성 결과의 난이도와 풀이 가능성을 확인하는 통합 테스트 추가
