## 프로젝트 개요

> C/C++ 코드의 취약점을 탐지하는 AI 모델을 구현하고, 취약한 코드와 해당 취약점이 수정된 코드를 구분하는 능력을 분석한다. 공개 취약점 사례 분석을 통해 보안 기초를 학습한 뒤, 관련 논문과 공개 데이터셋을 활용하여 모델 학습 및 평가를 수행한다. 모델의 오탐·미탐과 코드 변형에 따른 예측 변화를 분석하고, 데이터 증강 실험을 통해 개선 효과와 한계를 검증한다.

## 기대 효과

- C/C++ 메모리 취약점의 발생 원인과 패치 원리를 이해하고, 코드 분석 및 디버깅 역량을 기른다.
- 보안 논문을 읽고 핵심 실험을 일부 재현하면서 AI 기반 취약점 탐지 연구의 방법과 한계를 이해한다.
- 학습한 모델, 재현 가능한 실험 코드, 평가 결과 및 분석 보고서를 개인 프로젝트 결과물로 확보한다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- AI를 활용한 취약점 탐지 연구에서는 모델의 탐지 성능뿐 아니라 패치 전후 구분 능력, 데이터 누수, 코드의 표면적 특징에 대한 의존이 중요한 평가 문제로 다뤄지고 있다.
- 보안 입문 단계에서 C/C++ 취약점의 원리를 학습하고, 이를 논문 분석과 모델 구현으로 연결하여 보안 및 머신러닝 기초를 함께 쌓고자 한다.
- 모델이 취약점과 관련된 코드 차이를 구분하는지 실험하고, 실패 사례를 분석하여 탐지 모델의 적용 가능성과 한계를 파악한다.

## 2. 프로젝트 세부내용

- **1~2주차: 보안 기초 학습 및 취약점 사례 분석**
  - C/C++의 포인터, 배열, 동적 메모리와 메모리 경계 개념을 학습한다.
  - 공개 메모리 취약점 사례 2~3개를 분석하고, 그중 1개를 로컬 환경에서 재현하여 발생 원인과 패치 내용을 정리한다.
- **3주차: 관련 논문 분석 및 데이터 구성**
  - PrimeVul을 중심으로 문제 정의, 데이터 구성, 학습 방법 및 평가 지표를 정리하고, LLMxCPG의 문맥 활용 방법을 비교 분석한다.
  - 공개 데이터의 유형별 표본 수와 메타데이터를 확인하고, 메모리 취약점 유형 1~2개를 중심으로 실험 범위를 확정한다.
  - 공식 데이터 분할을 우선 활용하며, 동일 취약점의 패치 전후 코드와 중복·변형 코드가 학습과 평가 데이터에 나뉘어 들어가지 않도록 점검한다.
- **4~5주차: 취약점 탐지 모델 구현 및 학습**
  - TF-IDF와 로지스틱 회귀를 활용한 기본 분류 모델을 구현하여 비교 기준으로 사용한다.
  - 사전학습 코드 모델에 이진 분류기를 추가하고, 선정한 데이터로 파인튜닝하여 취약 여부를 예측하는 모델을 구현한다.
  - 학습 설정, 데이터 구성 및 모델 가중치를 기록하여 실험을 재현할 수 있도록 한다.
- **6주차: 패치 전후 판별 및 오류 분석**
  - 동일한 평가 데이터에서 두 모델의 정밀도, 재현율, F1 점수와 오탐·미탐을 비교한다.
  - 취약 코드와 해당 취약점이 수정된 코드의 쌍을 모두 올바르게 판별하는 비율을 측정한다.
  - 대표 실패 사례의 코드와 패치를 직접 읽고, 입력 문맥 부족이나 표면적 특징 의존 등 가능한 원인을 분석한다.
- **7주차: 데이터 증강 및 개선 실험**
  - 코드의 동작을 유지하도록 변수 이름을 일관되게 변경한 사례를 구성하고 예측의 안정성을 확인한다.
  - 학습 데이터에 코드 변형 사례를 추가한 모델과 기존 모델을 동일한 평가 조건에서 비교한다.
  - 개선 효과뿐 아니라 새로운 오탐·미탐과 일반화의 한계도 기록한다.
- **8주차: 결과 정리 및 최종 검증**
  - 논문 분석 내용, 모델 구현 과정, 평가 결과와 한계를 보고서로 정리한다.
  - 실행 방법과 개발환경을 README에 작성하고, 저장한 모델과 코드로 평가 결과를 다시 확인한다.
  - 실제 활동 일정과 시험기간에 따라 주차별 수행 기간을 조정한다.

## 3. 프로젝트 기대효과

- 취약점 사례와 수정 코드를 직접 비교하면서 메모리 안전성 및 안전한 코드 작성 원칙을 이해할 수 있다.
- 데이터 전처리, 모델 학습, 성능 평가 및 오류 분석을 포함한 AI 보안 실험 과정을 경험할 수 있다.
- 논문의 핵심 실험을 축소 재현하고 결과를 비판적으로 해석하는 역량을 기를 수 있다.
- 코드의 표면적 특징과 실제 취약점 관련 차이를 구분하는 모델 평가 방법을 이해하고, 향후 바이너리 분석 및 문맥 기반 취약점 탐지 연구로 확장할 기반을 마련할 수 있다.

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- C/C++ 메모리 구조와 머신러닝에 대한 사전지식 부족으로 초기 분석과 환경 구성에 시간이 소요될 수 있다. 분석 대상을 제한하고 단계별 실습을 병행한다.
- 공개 데이터의 라벨 오류, 중복 및 클래스 불균형이 평가 결과에 영향을 줄 수 있다. 데이터 구성과 분할 기준을 기록하고 대표 사례를 수동으로 확인한다.
- 함수 단위 코드만으로는 호출 관계와 외부 입력의 흐름을 충분히 파악하기 어려울 수 있다. 오류 분석 시 원본 프로젝트와 패치 정보를 함께 확인한다.
- GPU 자원과 학습 시간의 제약이 발생할 수 있다. 소규모 데이터로 먼저 실험하고, 확보한 환경에 맞춰 모델 크기와 학습 설정을 조정한다.
- 코드 변형이 프로그램의 동작을 바꾸면 평가의 타당성이 낮아질 수 있다. 일관된 변수명 변경을 사용하고, 대표 변형 사례의 동작 유지 여부를 확인한다.
- 데이터 증강을 적용하더라도 성능 향상이 나타나지 않을 수 있다. 모델 구현, 비교 실험 및 실패 원인 분석을 완료 기준으로 삼아 결과를 정리한다.

## 5. 프로젝트 수행시 요구사항 (개발환경, 사전지식 등)

- **개발환경:** Linux 기반 실습 환경, Python, C/C++ 컴파일러 및 모델 학습에 사용할 GPU 환경.
- **보안 사전지식:** C/C++ 포인터·배열·동적 메모리, 버퍼 경계, 취약점과 패치의 개념, GDB를 활용한 기본 디버깅.
- **AI 사전지식:** 지도학습, 이진 분류, 학습·검증·평가 데이터 분리, 과적합, 정밀도·재현율·F1 점수, 사전학습 모델과 파인튜닝.
- **논문 분석:** 연구 문제, 기존 방법의 한계, 제안 방법, 실험 설계 및 결과를 정리하는 능력.
- **실험 관리:** Git을 활용한 코드 관리와 데이터 출처·버전·학습 설정 기록. 필요한 사전지식은 프로젝트 초기에 학습하며 보완한다.

## 개인 수행 계획

- **주요 수행 항목:** 보안 기초 학습, 공개 취약점 재현 및 패치 분석, 관련 논문 분석, 데이터 구성, 기본 모델과 코드 모델 학습, 패치 전후 판별 평가, 데이터 증강 실험 및 결과 정리.
- **예상 산출물:** 취약점 사례 분석 자료, 관련 논문 분석 노트, 데이터 구성 및 분할 기록, 모델 학습·평가 코드와 학습된 모델, 패치 전후 및 코드 변형 평가 결과, 최종 분석 보고서, 실행 방법을 포함한 README.
- **검증 방법:** 동일한 평가 데이터에서 기본 모델과 코드 모델의 정밀도·재현율·F1 점수 및 오탐·미탐을 비교한다. 패치 전후 코드 쌍의 동시 정답률과 코드 변형에 따른 예측 변화를 측정한다. 분류 임계값은 검증 데이터에서 결정하고 평가 데이터에는 고정하여 적용한다. 데이터 증강 전후 모델을 같은 조건으로 비교하고, 대표 실패 사례를 수동으로 분석한다. 데이터 버전, 학습 설정과 난수 시드를 기록하여 평가를 재실행한다.
