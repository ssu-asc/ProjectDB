## 이번 회차 세부 진행 내용

### 1. 인증 영역(A-2 후속) - 로그인 전후 세션 식별자 갱신 여부 점검

`login.plaync.com`의 정상 로그인 흐름을 대상으로, 로그인 이전에 발급된 세션 식별자가 로그인 성공 후에도 그대로 유지되는지 수동으로 점검하였다.

#### 테스트 목적

로그인 이전의 세션 식별자가 인증 완료 후에도 변경되지 않는 경우 세션 고정 공격에 악용될 가능성이 있다. 이를 확인하기 위해 동일한 로그인 흐름에서 서버가 설정한 로그인 전후의 `JSESSIONID` 값을 비교하였다.

#### 테스트 절차

1. 새로운 브라우저 세션에서 `login.plaync.com` 로그인 페이지에 접속
2. 로그인 전에 서버가 반환한 응답의 `Set-Cookie` 헤더를 Burp Suite에서 확인
3. 본인 소유 테스트 계정으로 정상 로그인
4. 로그인 완료 후 서버가 반환한 응답의 `Set-Cookie` 헤더를 확인
5. 로그인 전후에 발급된 동일 이름의 `JSESSIONID` 값을 비교

---

### 2. 로그인 전 세션 쿠키 확인

로그인 페이지에 접속하는 과정에서 서버가 `JSESSIONID` 쿠키를 설정하는 것을 확인하였다.

```http
Set-Cookie: JSESSIONID=redacted; Path=/;
```

---

### 3. 로그인 후 세션 쿠키 확인

```http
Set-Cookie: JSESSIONID=redacted; Path=/;
```

로그인 후 발급된 `JSESSIONID`는 로그인 전에 확인한 값과 서로 달랐다.

---

### 4. 결과 분석

동일한 정상 로그인 흐름에서 로그인 전후의 `JSESSIONID`를 비교한 결과, 로그인 성공 후 세션 식별자가 새로운 값으로 갱신되는 것을 확인하였다.

이는 인증 수준이 변경되는 시점에 기존 세션 식별자를 계속 사용하지 않고 새로운 세션 식별자를 발급하는 동작으로 판단된다. 따라서 관찰된 로그인 흐름에서는 로그인 전 세션 식별자가 인증 후에도 그대로 유지되는 현상이 확인되지 않았다.

---

### 테스트 결과 요약

| 점검 항목 | 결과 |
| --- | --- |
| 로그인 전 세션 쿠키 | `JSESSIONID` 발급 확인 |
| 로그인 후 세션 쿠키 | `JSESSIONID` 재발급 확인 |
| 로그인 전후 값 비교 | 서로 다른 값으로 확인 |
| 세션 식별자 갱신 | 정상 동작으로 판단 |
| 취약점 발견 여부 | 발견하지 못함 |

### 결론

`login.plaync.com`의 정상 로그인 과정에서 로그인 전후의 `JSESSIONID`를 비교한 결과, 로그인 성공 후 세션 식별자가 기존 값과 다른 값으로 갱신되었다. 따라서 이번 점검 범위에서는 로그인 전 세션 식별자가 인증 후에도 유지되는 현상이 확인되지 않았으며, 세션 고정과 관련된 취약점은 발견하지 못하였다.
