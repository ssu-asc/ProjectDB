- 단계별 실습 코드, 익스플로잇 코드 및 분석 문서를 GitHub에 정리하여 이후 포너블 학습과 프로젝트에 활용할 수 있다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- 시스템 프로그래밍 과목에서 배우는 프로세스의 가상주소 공간, 함수 호출, 스택과 힙, 시스템 콜, 파일 디스크립터, ELF 및 공유 라이브러리 등의 개념을 보안 관점에서 학습한다.
- 이론 학습에 그치지 않고 직접 작성하거나 공개된 취약 바이너리를 GDB로 분석하고, pwntools를 이용해 익스플로잇을 구현하며 프로그램 내부 동작을 이해한다.
- 기초적인 Stack Buffer Overflow부터 ROP, Format String, 기초 Heap 취약점까지 난이도를 단계적으로 높여 포너블 학습 기반을 마련한다.
- 각 취약점의 공격 원리뿐 아니라 Canary, NX, PIE, ASLR, RELRO 등의 보호기법과 안전한 코드 수정 방법을 함께 분석한다.
- 최종적으로 공개 포너블 문제 또는 공개 취약 바이너리 하나를 독립적으로 분석하고 익스플로잇하는 것을 목표로 한다.

## 2. 프로젝트 세부내용

- 1단계에서는 C 포인터, 배열, 함수 호출 과정과 Linux 프로세스의 Code, Data, Heap, Stack 영역을 학습한다. GDB와 Pwndbg를 이용해 함수 호출 전후의 레지스터, 스택 프레임, 반환 주소 변화를 직접 관찰한다.
- 2단계에서는 ELF 파일의 Header, Section, Segment, Symbol 구조를 분석한다. `file`, `readelf`, `objdump`, `nm`, `ldd`, `checksec` 등의 도구를 사용하여 바이너리의 실행 구조와 적용된 보호기법을 확인한다.
- 3단계에서는 입력 길이를 검사하지 않는 C 프로그램을 대상으로 Stack Buffer Overflow를 재현한다. pwntools의 cyclic pattern을 이용해 반환 주소까지의 오프셋을 구하고, 실행 흐름을 지정된 함수로 변경하는 익스플로잇을 구현한다.
- 4단계에서는 `execve()` 시스템 콜과 프로세스 실행 구조를 학습하고, NX 적용 전후의 차이를 분석한다. NX가 적용된 환경에서는 기존 코드 조각을 활용하는 ROP와 ret2libc의 기본 원리를 실습한다.
- 5단계에서는 ASLR과 PIE로 인해 실행 주소가 변경되는 원리를 학습한다. 프로그램 또는 libc 주소를 유출하고 기준 주소를 계산하여 익스플로잇에 활용하는 과정을 실습한다.
- 6단계에서는 Format String 취약점을 통해 스택 값과 주소가 노출되는 원리를 분석하고, 사용자 입력을 출력 함수의 서식 문자열로 직접 사용하는 코드와 안전하게 수정한 코드를 비교한다.
- 7단계에서는 GOT, PLT 및 동적 링킹 구조를 학습하고 Partial RELRO와 Full RELRO 적용에 따른 메모리 쓰기 가능 여부와 익스플로잇 방식의 차이를 분석한다.
- 8단계에서는 `malloc()`과 `free()`의 동작, Heap 영역의 객체 배치 및 해제된 메모리의 재사용 원리를 학습한다. 간단한 Use After Free와 Double Free 예제를 분석하고 수정 전후의 동작을 비교한다.
- 9단계에서는 동일한 취약 바이너리를 보호기법 설정별로 빌드하여 Canary, NX, PIE, ASLR, RELRO가 익스플로잇 과정에 미치는 영향을 비교한다.
- 10단계에서는 지금까지 학습한 내용을 바탕으로 공개 포너블 문제 또는 공개 취약 바이너리 하나를 선정하여 정적 분석, 동적 분석, 익스플로잇 구현, 패치 및 재검증 과정을 수행한다.
- 모든 실습은 개인 로컬 Linux 환경 또는 격리된 가상환경에서 진행하며, 각 단계별로 취약 코드, 수정 코드, 익스플로잇 코드, 실행 결과와 분석 문서를 GitHub에 기록한다.

## 3. 프로젝트 기대효과

- 시스템 프로그래밍에서 학습한 개념이 실제 프로그램의 실행 및 취약점 발생 과정과 어떻게 연결되는지 이해할 수 있다.
- C 언어의 포인터와 메모리 사용, x86-64 어셈블리, 함수 호출 규약, 시스템 콜 및 ELF 구조에 대한 이해도를 높일 수 있다.
- GDB와 Pwndbg를 이용해 크래시 원인, 레지스터 상태, 스택과 힙의 변화를 분석하는 능력을 기를 수 있다.
- pwntools를 활용하여 입력 생성, 프로세스 통신, 주소 계산 및 익스플로잇 실행을 자동화할 수 있다.
- 취약점 재현뿐 아니라 보호기법과 패치 적용 전후를 비교함으로써 공격과 방어 양쪽의 관점에서 바이너리를 이해할 수 있다.
- 프로젝트 종료 후에도 워게임, CTF, 오픈소스 취약점 분석 및 팀 프로젝트에 재사용할 수 있는 개인 학습 자료와 코드 저장소를 확보할 수 있다.

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- C 포인터, 메모리 구조 및 어셈블리 기초가 부족할 경우 초기 바이너리 분석에 많은 시간이 필요할 수 있다.
- 운영체제, CPU 아키텍처, glibc 버전 및 컴파일 옵션에 따라 동일한 익스플로잇의 실행 결과가 달라질 수 있다.
- ASLR, PIE, Canary, NX, RELRO 등의 보호기법이 동시에 적용된 문제는 초기에 분석 난도가 높을 수 있다.
- Heap 취약점은 glibc 버전에 따라 내부 구조와 활용 기법이 달라지므로 프로젝트 범위를 기초적인 Heap 구조와 취약점 분석으로 제한할 필요가 있다.
- 공개 익스플로잇 코드를 그대로 실행하는 데 그칠 가능성이 있으므로, 각 코드의 동작 원리와 메모리 변화를 직접 설명하고 재구현하는 과정을 포함해야 한다.
- 특정 실습에서 익스플로잇 구현에 실패할 경우 크래시 재현, 원인 분석, 보호기법에 따른 실패 지점 및 패치 검증을 산출물로 정리한다.

## 5. 프로젝트 수행시 요구사항 (개발환경, 사전지식 등)

- C 언어의 변수, 배열, 포인터, 구조체, 함수 및 동적 메모리 할당에 대한 기초 지식
- Linux 명령어와 파일·프로세스·권한에 대한 기본적인 이해
- 시스템 프로그래밍 수업에서 학습하는 파일 디스크립터, 프로세스, 시스템 콜, 메모리 구조 및 ELF 관련 내용
- x86-64 레지스터와 기본 어셈블리 명령어에 대한 단계적인 학습
- Ubuntu 기반 Linux 가상환경과 GCC를 이용한 C 프로그램 컴파일 환경
- GDB, Pwndbg, pwntools, checksec, binutils 등의 바이너리 분석 및 익스플로잇 도구
- 실습 결과와 분석 과정을 지속적으로 정리할 GitHub 저장소

- **주요 수행 항목:** 시스템 프로그래밍 및 포너블 기초 학습, Linux 프로세스 메모리와 ELF 구조 분석, Stack Buffer Overflow·Format String·ROP·기초 Heap 취약점 실습, pwntools 익스플로잇 구현, 보호기법 비교, 취약 코드 패치 및 공개 포너블 문제 종합 분석
- **예상 산출물:** 단계별 취약·수정 C 코드, pwntools 익스플로잇 코드, GDB 분석 자료, 보호기법별 비교표, 공개 포너블 문제 분석 보고서, 최종 시연 영상 또는 발표 자료, 전체 학습 과정을 정리한 GitHub 저장소
