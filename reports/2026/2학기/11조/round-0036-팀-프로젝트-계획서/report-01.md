## 프로젝트 개요

> Microsoft Security Response Center(MSRC)의 공식 버그 바운티 프로그램을 조사하고, 허용된 범위 내에서 Microsoft 제품 또는 Microsoft 소유 오픈소스 프로젝트의 보안 취약점을 분석한다. 발견한 취약점은 재현 절차, 보안 영향, 증명 자료(PoC), 개선 방안을 포함한 보고서로 작성하여 MSRC Researcher Portal에 책임 있게 제보한다. 취약점을 발견하지 못하더라도 분석 과정과 보안 개선 방안을 정리하여 최종 연구 보고서와 발표 자료를 제작한다.

## 기대 효과

실제 버그 바운티 절차를 통한 정보보안 실무 경험 습득, 
웹·소프트웨어 취약점의 발생 원인과 대응 방법 이해, 
취약점 재현, 위험도 평가, 보고서 작성 능력 향상,
협업과 역할 분담을 통한 문제 해결 능력 강화,
책임 있는 공개와 정보보안 윤리 및 관련 법규 이해

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)
소프트웨어와 클라우드 서비스의 활용이 확대되면서 취약점의 조기 발견과 대응이 중요해지고 있다.
MSRC의 공식 버그 바운티 프로그램에 참여하여 이론 중심의 보안 학습을 실제 취약점 분석 과정에 적용한다.
공격 자체보다 취약점의 원인, 보안 영향 및 개선 방법을 연구하여 책임 있는 보안 연구 역량을 기른다.
공식 범위와 Rules of Engagement를 준수하며 합법적이고 윤리적인 보안 연구 문화를 익힌다.
팀원 간 분석 결과를 공유하고 검증하면서 협업 및 기술 문서 작성 능력을 향상한다.

## 2. 프로젝트 세부내용
MSRC 버그 바운티 프로그램의 참가 조건, 대상 제품, 허용·금지 행위 및 보고 절차를 조사한다.
팀원의 기술 수준과 실습 환경을 고려하여 Microsoft 소유 오픈소스 프로젝트 또는 테스트가 허용된 Microsoft 제품 중 연구 대상 1개를 선정한다.
대상의 구조, 주요 기능, 데이터 흐름, 인증·인가 방식 및 공격 표면을 분석한다.
다음과 같은 취약점 유형을 중심으로 점검한다.- 인증 및 접근 제어 오류
- 입력값 검증 미흡
- 정보 노출
- 경로 조작 및 파일 처리 취약점
- 종속성 및 오픈소스 구성요소 취약점
- 보안 설정 오류
- 서버 측 요청 위조, 코드 삽입 등 프로그램 범위에서 허용된 항목

정적 코드 분석과 동적 분석을 병행하고, 모든 실험은 개인 테스트 계정, 로컬 환경 또는 격리된 가상환경에서 수행한다.
의심되는 취약점을 발견하면 최소 두 명의 팀원이 독립적으로 재현 여부를 검증한다.
검증된 결과에 대해 발견 과정, 재현 절차, 예상 피해, 증명 자료, 완화 방안을 포함한 영문 보고서를 작성한다.
유효한 취약점은 외부에 먼저 공개하지 않고 MSRC Researcher Portal을 통해 비공개로 제출한다.
취약점을 발견하지 못한 경우에도 분석 범위, 사용한 방법, 실패 원인, 개선 제안을 정리하여 최종 결과물로 제출한다.
## 3. 프로젝트 기대효과
실제 서비스와 오픈소스 프로젝트를 분석하면서 실무 중심의 보안 역량을 습득할 수 있다.
취약점의 발견뿐만 아니라 재현, 영향 분석, 대응 방안 제시까지 전체 과정을 경험할 수 있다.
영문 취약점 보고서 작성과 기술 발표를 통해 의사소통 능력을 향상할 수 있다.
분석 결과가 인정되는 경우 MSRC의 포상 또는 연구자 인정 프로그램에 참여할 가능성이 있다.
취약점이 발견되지 않더라도 분석 방법과 시행착오를 체계적으로 정리한 연구 결과물을 확보할 수 있다.
향후 정보보안 분야 진학, 대회 참가, 포트폴리오 제작에 활용할 수 있다.

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)
실제 취약점을 반드시 발견할 수 있다는 보장이 없으며, 이미 제보된 중복 취약점일 가능성이 있다.
프로그램별 대상 제품, 허용 범위 및 제외 항목이 다르고 운영 중 변경될 수 있다.
미숙한 테스트로 서비스 장애나 타인의 데이터 접근이 발생하지 않도록 각별한 주의가 필요하다.
클라우드 서비스와 일부 개발 도구 사용 과정에서 비용이 발생할 수 있다.
분석 대상의 규모가 크거나 기술 난도가 높으면 프로젝트 기간 내 충분한 분석이 어려울 수 있다.
MSRC의 검토와 답변에 상당한 시간이 소요되어 프로젝트 종료 전 결과가 확정되지 않을 수 있다.
공개 전까지 취약점 정보를 비밀로 유지해야 하므로 발표 자료에는 민감한 세부정보를 제외해야 한다.
팀원별 프로그래밍 및 보안 지식의 차이로 업무 편중이 발생할 수 있다.

## 5. 프로젝트 수행시 요구사항 (프로젝트 구성원, 개발환경 등)
팀원 전원이 MSRC 프로그램 규정, 안전 조항 및 책임 있는 공개 원칙을 사전에 숙지해야 한다.
테스트 시작 전 대상 제품이 현재 공식 바운티 범위에 포함되는지 다시 확인해야 한다.
반드시 본인이 소유한 테스트 계정과 데이터를 사용하고, 타인의 계정 및 데이터에 접근하지 않는다.
서비스 거부 공격, 대량 트래픽 발생, 피싱, 사회공학, 악성코드 유포 등 금지된 행위는 수행하지 않는다.
개인정보나 민감한 데이터를 발견하면 추가 접근 및 저장을 즉시 중단하고 MSRC에 알린다.
테스트 범위가 불명확한 경우 임의로 진행하지 않고 MSRC에 문의한 후 수행한다.
분석 자료와 PoC는 접근 권한이 제한된 저장소에 보관하고, MSRC의 수정 및 공개 허가 전까지 외부에 공유하지 않는다.
Windows 또는 Linux 가상환경, Git, 프로그래밍 언어, 웹 프록시 및 코드 분석 도구를 사용할 수 있는 환경이 필요하다.
주 1회 진행 상황을 공유하고 분석 기록, 회의록 및 테스트 결과를 문서화한다.
