## 프로젝트 개요

> 사용자가 얼굴 사진을 SNS에 올리기 전에 보호 처리(워터마크, 지각 핑거프린트, 스왑기를 겨냥한 적대적 노이즈)를 해 둔다. 나중에 나온 이미지·영상에서는 그 사람의 얼굴이 등장하는지 찾는다. 그리고 그것이 내 원본의 재배포인지, 원본을 변조한 것인지, 등록되지 않은 콘텐츠에 내 얼굴이 나온 것인지를 여러 독립 증거로 판정한다.
>
> 해결하려는 문제는 두 가지다. 첫째, 기존 대응이 딥페이크 탐지기 하나, 워터마크 하나처럼 단일 기술에 의존한다. 둘째, "당신의 사진이 학습에 쓰였다"처럼 현재 기술로 증명할 수 없는 주장을 한다. 이 프로젝트는 각 계층이 어디까지 되고 어디서 실패하는지를 직접 측정하고, 측정된 만큼만 말하는 시스템을 만든다.

## 기대 효과

- 공개 사진이 딥페이크 재료로 쓰이는 것을 사전에 어렵게 만드는 보호 수단을 제공한다.
- 사용자와 닮은 얼굴이 나온 콘텐츠를 찾아, 재배포·변조·신원 등장을 근거 문장과 함께 구분해 보고한다.
- 워터마크·보호 노이즈·딥페이크 탐지기가 실제 SNS 조건(압축, 리사이즈, 크롭, 회전)과 공격자 앞에서 어디까지 버티는지를 재현 가능한 수치로 남긴다.
- 한국인 사용자 기준으로 얼굴 인식 임계값을 검증해, 해외 벤치마크로 정한 기준을 그대로 쓸 때의 오인 위험을 확인한다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

**추진 배경**

- 딥페이크 제작 도구의 진입 장벽이 크게 낮아졌다. 얼굴 교체(face swap), 사진 한 장으로 얼굴을 복제하는 생성기(IP-Adapter FaceID, InstantID), 사진 몇 장으로 학습하는 LoRA가 그 예이다. 그래서 얼굴 사진을 공개한 개인은 누구나 합성 콘텐츠의 재료가 될 수 있다.
- 현재의 대응 기술은 서로 다른 문제를 풀고, 서로 다른 조건에서 실패한다.
  - 딥페이크 탐지기는 학습하지 않은 생성기와 SNS 재압축에 약하다.
  - 워터마크는 파일을 지킬 뿐 신원을 지키지 못한다. 생성 모델은 원본의 워터마크를 다시 그리지 않는다.
  - 적대적 노이즈는 겨냥한 모델 밖으로 전이되지 않을 수 있다.
- 일부 서비스는 "당신의 사진이 딥페이크 학습에 사용되었습니다"처럼 현재 기술로 증명할 수 없는 주장(학습 데이터 귀속)을 사용자에게 보여 준다.

**취지**

- 하나의 기술이 문제를 해결한다고 가정하지 않는다. 대신 신원 유사도, 워터마크, 핑거프린트, 출처(C2PA), 딥페이크 탐지를 독립 신호로 두고 증거를 결합하는 Defense-in-Depth 구조로 설계한다.
- 핵심 연구 질문은 다음과 같다.

  > 사용자의 얼굴 이미지에 보호를 적용한 뒤, 그 사용자와 얼굴 유사도가 높은 콘텐츠를 찾아내고, 그 콘텐츠가 합성·조작되었을 가능성을 하나가 아니라 여러 개의 독립적인 증거로 평가할 수 있는가?

- 문제를 둘로 나눈다.
  - Problem A(학습 데이터 귀속)는 범위 밖으로 둔다. 시스템도 이를 주장하지 않는다.
  - Problem B(신원 유사도 탐지)는 MVP로 구현한다.
- 기준을 통과하지 못한 신호는 판정에서 빼고, 그 이유와 측정값을 문서로 남긴다. 부정적 결과도 결과로 기록한다.

## 2. 프로젝트 세부내용

**위협 모델**

- 보호 대상은 얼굴 사진을 공개적으로 올리는 개인이다.
- 공격자는 사진을 모아 합성 이미지·영상을 만들고 퍼뜨린다. 그 과정에서 재인코딩, 크롭, 리사이즈, 스크린샷, 회전을 할 수 있다. 워터마크를 지우거나 위조하고, 보호 노이즈를 정화하려 할 수도 있다.
- 공격자의 지식 수준은 세 단계로 나눠 본다.
  1. 마크를 모르는 공격자
  2. 알고리즘을 아는 공격자
  3. 디코더·키까지 가진 공격자

**시스템 구성**

```text
[보호]  사용자 사진 → 신원 등록(얼굴 임베딩) → 보호 파이프라인
                                              ├ 워터마크 (DCT 격자 / 학습형)
                                              ├ 지각 핑거프린트
                                              └ 적대적 노이즈 (스왑기 인코더 겨냥)
                                              → 보호된 사진 + 자산 기록

[탐지]  의심 이미지·영상 → 전처리(해시·핑거프린트·워터마크 판독)
        → 얼굴 검출 → 정렬 → 임베딩 → 신원 검색
        → 후보 필터 (후보 임계값을 넘은 얼굴만 다음 단계로)
        → 딥페이크 탐지 · 워터마크 탐지 · 핑거프린트 매칭 · 출처 확인
        → 증거 종합 → 판정 엔진 → 근거가 붙은 보고서
```

- **후보 게이팅:** 값싼 신원 유사도를 먼저 계산하고, 사용자와 닮은 얼굴에만 비싼 탐지기를 돌린다. 계산 비용과 무관한 오탐을 함께 줄이기 위해서다.
- **교체 가능한 백엔드:** 검출기·임베더·탐지기를 모두 추상 인터페이스와 레지스트리 뒤에 둔다. 그래서 모델을 바꿔 가며 같은 조건으로 비교할 수 있다.

**구현 항목**

1. **얼굴 인식:** SCRFD/YuNet 검출, 5점 정렬, ArcFace 임베딩, 좌우 반전 TTA를 쓴다. 작은 얼굴이나 화면을 꽉 채운 얼굴처럼 검출이 실패하는 경우에는 확대·패딩으로 다시 검출한다. 후보 임계값과 고신뢰 임계값을 2단계로 둔다.
2. **워터마크:**
   - 타일 DCT 격자 워터마크에 재동기화(크롭·회전·배율 탐색)를 붙인다.
   - 비밀키로 계수 배치를 섞어 위조를 막는다.
   - 딥페이크를 거쳐도 남도록 학습형 워터마크(HiDDeN 구조의 인코더·디코더)를 따로 만든다. 학습 중 확산 모델 VAE 왕복을 미분 가능한 대리 왜곡으로 넣는다.
3. **보호 노이즈:**
   - 인식 회피 클로킹(SPSA·PGD)부터 검증한다.
   - 이어서 스왑기가 내부적으로 쓰는 얼굴 인코더(ArcFace)를 직접 겨냥한 8/255 PGD 노이즈(EOT 포함)를 `protect --mode shield`로 만든다.
   - LoRA 학습 방어는 공개 도구(PhotoGuard, Anti-DreamBooth, Mist v2)를 같은 프로토콜로 비교한다. 스왑 방어와 한 사진에 함께 넣는 방법도 연구한다.
4. **딥페이크 탐지:** 공개 체크포인트, 직접 학습한 CNN, FaceForensics++로 학습한 모델을 같은 ONNX 어댑터로 연결한다. 사전에 정한 채택 게이트를 통과한 모델만 판정에 넣는다.
5. **판정 엔진:** 가중합 위험 점수 대신 상황별 판정 범주(`own_copy`, `own_altered`, `identity_match`, `review` 등)와 근거 문장을 낸다. 사용자가 "왜 이런 결론이 나왔는지"를 읽을 수 있게 하기 위해서다.
6. **영상 처리:** 2fps로 샘플링하고, 샘플링한 얼굴은 전부 임베딩한다. 진짜 장면 사이에 짧게 끼운 가짜도 놓치지 않기 위해서다.
7. **출처:** 해시 체인으로 로컬 계보를 기록하고, C2PA 콘텐츠 자격증명의 서명·해시를 검증한다.
8. **콘텐츠 수집(스캔):** 사용자가 지정한 폴더·URL에서 제한적으로 크롤링한다.
   - robots.txt를 지키고, 내부망을 차단한다.
   - 요청 간격·페이지 수·파일 크기에 상한을 둔다.
   - 등록 신원과 관련된 결과만 보고한다.
9. **인터페이스:** `deepshield` CLI(`enroll`, `protect`, `analyze-image`, `scan`, `robustness-test` 등)와 FastAPI 기반 REST API를 만든다.

## 3. 프로젝트 기대효과

- **개인 사용자:** 사진을 올리기 전에 한 번의 명령으로 워터마크·핑거프린트·보호 노이즈를 넣을 수 있다. 의심 콘텐츠를 넣으면 "내 원본 재배포 / 내 원본 변조 / 내 얼굴 등장 / 무관"을 근거와 함께 받아 볼 수 있다.
- **정직한 보고:** 판정은 "사용자와 매우 닮은 얼굴이 등록되지 않은 콘텐츠에 나온다. 진위는 판단하지 않았다"처럼 측정된 만큼만 말한다. 그래서 과장된 경보나 엉뚱한 사람 지목을 줄인다.
- **연구 측면:** 워터마크, 보호 노이즈, 딥페이크 탐지기가 SNS 변환·딥페이크 생성·의도적 공격 앞에서 어디까지 버티는지를 같은 규칙으로 측정한다. 되는 것과 안 되는 것을 모두 재현 가능한 수치로 남긴다.
- **한국 사용자 관점:** 해외 벤치마크(LFW)로 정한 임계값이 한국인 얼굴에서 어떤 오인 위험을 갖는지 확인하고 조정한다.
- **확장성:** 교체 가능한 백엔드 구조라서, 더 나은 탐지기·인식기가 나오면 같은 게이트로 평가해 바로 연결할 수 있다.

| 해외 벤치마크 기준 임계값이 한국인 사용자에게 맞지 않을 수 있음 | 동아시아계 얼굴과 KoDF(한국인 딥페이크 데이터셋)로 사칭 점수 꼬리를 다시 재서 임계값 조정 |
| 데이터셋 약관과 실존 인물 데이터 취급 | KoDF는 내국인 신청·국외 반출 금지 조항에 따라 로컬에서만 사용. 실존 인물 사진, 생성 이미지, 학습된 가중치는 저장소에 커밋하지 않고 재생성 스크립트만 제공 |
| 공격자가 워터마크를 의도적으로 지우거나 위조 | 공격자 지식 수준별로 제거·위조 비용을 측정하고, 비밀키 도입과 다중 계층으로 대응 |
| 대부분의 SNS가 robots.txt로 크롤러를 막음 | 크롤러는 robots.txt를 존중하고, 사용자가 직접 준 폴더·URL 검사를 기본 경로로 둠 |

## 개인 수행 계획

- **주요 수행 항목:**
  - 얼굴 검출·정렬·임베딩·등록·매칭과 이미지·영상 분석 파이프라인 구현
  - 보호 파이프라인: DCT 격자·학습형 워터마크, 지각 핑거프린트, 스왑기 인코더를 겨냥한 보호 노이즈(`shield` 모드)
  - 판정 엔진: 재배포 / 변조 / 신원 등장을 구분하는 판정 범주와 근거 문장
  - 딥페이크 탐지기 어댑터와 채택 게이트, 공개·자체 학습 탐지기 평가
  - 출처(해시 체인, C2PA 검증), 폴더·URL·크롤러 스캔, CLI와 REST API
  - 강건성 벤치마크: SNS 변환, 딥페이크 생성(그래픽·GAN·확산), 워터마크 제거·위조 공격, LoRA·단일 사진 생성기
  - 한국인 얼굴 기준 임계값 재검증
- **예상 산출물:**
  - DeepShield 소스 코드 저장소 (`deepshield` CLI, REST API)
  - 재현 가능한 평가 스크립트(`scripts/`)와 결과 파일(`data/results/`)
  - 되는 것과 안 되는 것을 수치로 정리한 README, 연구 과제별 보고서(부정적 결과 포함)
  - 단위·회귀 테스트 스위트
- **검증 방법:**
  - 정확도 하나만 보고하지 않고, 대상마다 지표를 따로 둔다.
    - 얼굴 매칭: TPR, FPR, ROC-AUC, EER, 사칭 점수 꼬리
    - 워터마크: 탐지율, 비트 정확도, 잘못된 코드 수, 마크 없는 사진의 오탐
    - 보호 노이즈: 화이트박스 / 모델 간 / 변환 후 효과를 나눠서, 스왑·생성 결과에서 원래 사람이 1위로 식별되는 비율
    - 화질: PSNR, SSIM
    - 판정: 상황별 기대 판정 일치율
  - 딥페이크 탐지기 채택 게이트를 미리 정한다.
    - 임계값은 보정용 진짜 사진 점수의 99.5 백분위수로 정한다.
    - 학습에 쓰지 않은 신원에서 원본·JPEG·작은 얼굴+H.264 조건 모두 진짜 오탐률의 95% 상한이 1% 이하여야 한다.
    - 조작 계열마다 재현율이 20% 이상이어야 한다.
    - 평가 세트로 학습한 모델은 거부한다.
  - 보호 노이즈의 화질 예산은 8/255(약 33dB)를 기준으로 한다. 이 예산에서 효과가 JPEG 압축 같은 평범한 변환보다 작으면 "효과 없음"으로 기록한다.
  - 공격자 지식 수준별(모름 / 알고리즘 앎 / 디코더·키 보유)로 워터마크 제거·위조 비용을 PSNR로 잰다.
  - 결과 파일에 시드, 커밋, 모델 버전, 실행 장치를 남겨 재현할 수 있게 한다. 별도 코드 리뷰로 측정과 문서 수치를 교차 검증한다.
