## 프로젝트 개요

> 로봇을 원격 제어할 때 주고받는 명령 통신이 암호화되지 않으면 제3자가 명령을 가로채거나 위조할 수 있다. 본 프로젝트는 별도 하드웨어 없이 두 프로그램(제어기<->로봇) 간 TCP 네트워크 통신으로 제어 명령을 패킷 분석 도구(Wireshark)로 가로채 평문 노출을 확인한다. 이후 통신 구간에 AES 암호화를 적용하되, 단일 적용에 그치지 않고 AES의 운영 모드(ECB·CBC·CTR·GCM)를 각각 적용해 패킷 노출 여부와 공격 성공 여부가 어떻게 달라지는지 비교한다. 전체 로봇 시뮬레이션 구현은 입문 단계에서 부담이 크다고 판단하여, 로봇 본체 대신 제어 명령 통신 구간에 집중해 범위를 한정한다.

## 기대 효과

- 로봇 제어 통신이 암호화 없이 전송될 때의 위험성을 실험으로 직접 확인
- AES 단독 적용만으로는 리플레이 공격·비트 플리핑 등을 막을 수 없음을 확인하고, 운영 모드 선택이 보안 수준을 좌우함을 이해
- 스니핑 공격과 암호화 방어의 원리를 코드·패킷 수준에서 이해
- 로봇/HRI 시스템 통신 보안의 기초 개념 습득

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- 로봇, 드론, IoT 기기는 통신으로 제어 명령을 주고받는데, 통신 구간이 암호화되지 않은 사례가 많음
- 암호화되지 않은 제어 통신은 제3자가 명령을 가로채거나(스니핑) 위조 명령을 주입해 로봇을 탈취할 수 있는 취약점이 됨
- 단순히 "암호화하면 안전하다"가 아니라,  어떤 방식(운영 모드)으로 암호화하느냐에 따라 방어 수준이 달라진다는 점을 직접 실험으로 확인하고자 함
- 보안 입문자로서 전공(AI소프트웨어)과 관심 분야(로봇, HRI)를 연결하여, 로봇 통신 보안이라는 실제적인 문제를 다뤄보고자 함
- 복잡한 하드웨어 대신 소프트웨어 시뮬레이션으로 핵심 원리에 집중하여, 입문 단계에서 소화 가능한 범위로 수행하고자 함

## 2. 프로젝트 세부내용

- 1) 기초 학습: TCP/IP 통신 기초, 패킷·스니핑 개념, 대칭키 암호화(AES) 및 운영 모드(ECB/CBC/CTR/GCM) 기초 학습
- 2) 실험 환경 구축
Python으로 로봇 제어 통신 시뮬레이션 구현: 제어기(명령 송신) ↔ 로봇(명령 수신·실행 출력)을 TCP 소켓으로 연결,
제어 명령 예시: "전진", "정지", "좌회전" 등 간단한 명령 프로토콜 정의
- 3) 스니핑 공격 재현
암호화 없이 전송되는 제어 명령을 Wireshark로 캡처해 평문 노출 확인,
(심화) 가로챈 명령을 그대로 재전송(리플레이)해 로봇이 반응하는지 확인
- 4) AES 운영 모드별 적용 및 비교
동일한 통신 구간에 아래 4가지 운영 모드를 각각 적용해 패킷을 캡처하고 변화를 관찰
    - ECB: 동일 명령 → 동일 암호문, 패킷에서 반복 패턴이 그대로 노출됨을 확인
    - CBC: 패턴은 가려지나 인증이 없어, 리플레이·변조 공격에 취약함을 확인
    - CTR: 스트림 방식 암호화 동작 확인 (GCM의 기반이 되는 모드)
    - AES-GCM: 암호화 + 무결성/인증(태그)까지 적용해 위조·변조가 탐지됨을 확인
- 5) 결과 분석 및 정리: 모드별 패킷 비교, 공격(스니핑/리플레이/변조) 성공 여부 비교표 작성, 동아리 내 발표
- (심화) GCM으로 변조는 탐지되지만 리플레이(동일 암호문 재전송)는 시퀀스 번호/타임스탬프를 추가해야 완전히 방어됨을 확인
- 모든 실험은 본인 PC 또는 개인 네트워크 환경에서만 수행하며, 외부 기기나 공용망 대상 공격은 하지 않음

### AES 운영 모드 비교 (예상 정리표)

| 모드 | 동일 명령의 암호문 | 패턴 노출 | 인증/무결성 | 리플레이·변조 방어 |
|------|------|:---:|:---:|------|
| **ECB** | 동일 | O (취약) | X | X |
| **CBC** | 상이 (IV) | X | X | X |
| **CTR** | 상이 (nonce) | X | X | X (스트림, GCM 기반) |
| **GCM** | 상이 (nonce) | X | O (태그) | 변조 탐지 O / 리플레이는 시퀀스 추가 필요 |

## 3. 프로젝트 기대효과

- 로봇 제어 통신의 스니핑 위험성을 패킷 캡처로 직접 확인
- 암호화 운영 모드별 보안 수준 차이(패턴 노출, 리플레이·변조 방어 여부)를 패킷 수준에서 비교
- "암호화 = 완전한 보안"이 아니며 인증·무결성이 함께 필요함을 이해
- 네트워크, 통신 보안에 대한 이해도를 로봇과 연결지어 키울 수 있음
- 이후 실제 하드웨어(Arduino/ESP32) 무선 통신 등 심화 프로젝트로 확장 가능 (만약  시간이 남는다면 시행해볼 예정)

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- 내부요인
보안, 네트워크 사전지식이 부족해 초반 학습 기간이 필요함 → 핵심 개념과 튜토리얼 위주로 범위 한정, 소켓 프로그래밍 경험 부족 → 간단한 예제부터 단계적으로 구현, 운영 모드가 4가지로 늘어 학습량 증가 → 모드별 핵심 차이(패턴/인증 유무) 중심으로 비교 포인트 압축
