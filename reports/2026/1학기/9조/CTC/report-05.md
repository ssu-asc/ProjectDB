## 이번 회차 세부 진행 내용

### 1. 인증 영역(A-2) - 로그아웃 후 세션 재사용 여부 점검

`login.plaync.com` 및 `id.plaync.com`의 인증 흐름을 대상으로, 로그아웃 이후 기존 세션을 이용한 마이페이지 재접근이 가능한지 점검하였다.

#### 테스트 목적

로그아웃 이후에도 기존 세션 쿠키가 포함된 요청으로 인증이 필요한 페이지에 접근할 수 있다면, 로그아웃 과정에서 서버 측 세션이 적절히 무효화되지 않았을 가능성이 있다. 이를 확인하기 위해 로그아웃 전후에 동일한 마이페이지 접근 요청을 전송하고 서버 응답을 비교하였다.

#### 테스트 절차

1. 본인 소유 테스트 계정으로 정상 로그인
2. 마이페이지(`id.plaync.com/account`) 접근 요청을 Burp Suite에서 캡처
3. 해당 요청을 Burp Repeater로 전송하여 정상 응답 확인
4. 브라우저에서 정상 로그아웃 수행
5. 로그아웃 전에 저장한 요청을 세션 쿠키를 변경하지 않은 상태로 재전송
6. 로그아웃 전후의 HTTP 응답 상태와 리다이렉트 위치 비교

---

### 2. 로그아웃 전 응답 확인

로그인 상태에서 캡처한 마이페이지 요청을 Burp Repeater로 전송했을 때 정상 응답이 반환되었으며, 본인 계정의 마이페이지에 접근할 수 있음을 확인하였다.

이 요청을 로그아웃 후 재사용 여부를 확인하기 위한 기준 요청으로 사용하였다.

---

### 3. 로그아웃 후 동일 요청 재전송 결과

브라우저에서 정상 로그아웃을 수행한 뒤, 로그아웃 전에 저장한 마이페이지 요청을 동일한 세션 쿠키와 함께 Burp Repeater로 다시 전송하였다.

서버는 다음과 같이 `HTTP/2 307 Temporary Redirect` 응답을 반환하였다.

```http
HTTP/2 307 Temporary Redirect
...
Location: https://login.plaync.com/nclogin/signin?return_url=https%3A%2F%2Fid.plaync.com%2Faccount
...
```

`Location` 헤더는 로그인 페이지를 가리키고 있었으며, 로그인 완료 후 원래 접근하려던 마이페이지로 돌아가기 위한 `return_url` 값이 포함되어 있었다.

---

### 4. 결과 분석

로그아웃 전에는 동일한 요청으로 마이페이지에 정상 접근할 수 있었으나, 로그아웃 후에는 서버가 마이페이지 내용을 반환하지 않고 로그인 페이지로 리다이렉트하였다.

이를 통해 점검한 요청 범위에서는 로그아웃 후 기존 세션을 사용한 인증 페이지 접근이 허용되지 않는 것을 확인하였다. 서버가 로그아웃 상태를 인식하고 재인증을 요구하므로, 관찰된 범위에서 로그아웃 처리와 접근 제어가 정상적으로 동작하는 것으로 판단하였다.

---

### 테스트 결과 요약

| 점검 항목                | 결과                                 |
| -------------------- | ---------------------------------- |
| 로그아웃 후 기존 요청 재전송     | `HTTP/2 307 Temporary Redirect` 반환 |
| 기존 세션을 이용한 마이페이지 재접근 | 허용되지 않음                            |
| 취약점 발견 여부            | 발견하지 못함                            |

### 결론

로그아웃 후 기존 세션 쿠키가 포함된 마이페이지 요청을 재전송한 결과, 서버는 마이페이지 내용을 반환하지 않고 로그인 페이지로 리다이렉트하였다. 따라서 이번 점검 범위에서는 로그아웃 후 기존 세션을 이용한 인증 페이지 재접근이 차단되는 것을 확인하였으며, 관련 취약점은 발견하지 못하였다.

### 5. API 인증 영역(B-4) - Store API 접근 통제 점검

`store.plaync.com`의 정상 화면에서 발생한 `store-bff.plaync.com` 요청을 대상으로, Cookie 제거 시 사용자별 데이터가 반환되는지 확인하였다.

#### 점검 조건

- 파인더갭 공식 VPN을 사용하고 범위 내 `store.plaync.com`, `store-bff.plaync.com`만 점검
- 정상 UI에서 관찰된 읽기 전용 `GET` 요청만 사용
- 1차 검증 5건, 요청 간 최소 60초, 동시 요청 1건으로 제한
- 자동 스캔·퍼징·경로 추측과 구매·결제 등 상태 변경 기능은 수행하지 않음

#### 관찰된 API

| API 경로                                     | 추정 용도          |
| ------------------------------------------ | -------------- |
| `/api/v1.0/user`                           | 사용자 세션 확인      |
| `/api/v1.0/unifiedStore/my/lin`            | 사용자별 Store 상태  |
| `/api/v1.0/unifiedStore/my/currency/lin`   | 보유 재화 정보       |
| `/api/v1.0/unifiedStore/my/membership/lin` | 멤버십 상태         |
| `/api/v1.0/unifiedStore/my/auth`           | 구매 또는 접근 가능 여부 |

#### Cookie 제거 결과

요청 구조와 Query는 유지하고 Cookie만 제거하였다. 응답 증적을 완전하게 확보한 결과는 다음과 같다.

| API 경로                                     | HTTP 응답  | 본문 결과                                          | 데이터 노출 |
| ------------------------------------------ | -------- | ---------------------------------------------- | ------ |
| `/api/v1.0/unifiedStore/my/currency/lin`   | `200 OK` | `data: null`, `status: 401`, `Session Expired` | 없음     |
| `/api/v1.0/unifiedStore/my/membership/lin` | `200 OK` | `data: null`, `status: 401`, `Session Expired` | 없음     |
| `/api/v1.0/unifiedStore/my/auth`           | `200 OK` | `data: null`, `status: 401`, `Session Expired` | 없음     |

`/api/v1.0/user`와 `/api/v1.0/unifiedStore/my/lin`도 단건 전송했으나 응답 증적을 완전하게 확보하지 못해 판정에서 제외하였다.

#### 결과

확인한 세 API는 Cookie가 없는 경우 사용자 데이터를 반환하지 않고 `Session Expired`로 처리하였다. 따라서 점검 범위에서는 미인증 요청을 이용한 Store API 접근 통제 우회가 확인되지 않았다.

### 6. Store 확장 Recon - 특화서버샵·포인트샵 점검

정상 UI에 노출된 링크와 카테고리만 이용하여 특화서버샵과 포인트샵으로 범위를 확장하였다. UI 전환 14회와 직접 API 검증 6건을 수행했으며, 5절을 포함한 직접 요청은 시간당 11건으로 제한하였다.

#### 특화서버샵 탐색

`/store/lindemon`에서 다음 공개 카테고리를 확인하였다.

| 카테고리  | `categoryKey`   | 관찰 결과  |
| ----- | --------------- | ------ |
| 월간 패스 | `DEMON-MONTHLY` | 상품 10건 |
| 주간 패스 | `DEMON-WEEKLY`  | 상품 2건  |
| 아이템   | `DEMON-A`       | 상품 6건  |
| 던전    | `DEMON-H`       | 상품 4건  |
| 부가서비스 | `DEMON-SERVICE` | 상품 없음  |

화면에서 사용자 세션, 재화, 멤버십, 인증 상태와 공개 상품 목록을 조회하는 API가 관찰되었다. 상품 목록은 `shopCode=lindemon`과 카테고리별 `categoryKey`로 구분되었다.

#### 포인트샵 탐색

| 게임       | 경로                   | 공개 상품 수 |
| -------- | -------------------- | -------:|
| 리니지      | `/point/linpoint`    | 17      |
| 리니지2     | `/point/lin2point`   | 6       |
| 아이온      | `/point/aionpoint`   | 4       |
| BNS NEO  | `/point/bnsneopoint` | 22      |
| 쓰론 앤 리버티 | `/point/tlpoint`     | 4       |
| 퍼플 포인트   | `/point/purplepoint` | 1       |

퍼플 포인트 상품 `어스토니시아 스토리 할인 쿠폰 (5000원)`의 공개 상세 화면까지 확인하였다. 수량은 1로 고정되어 있었으며 구매 버튼은 누르지 않았다.

포인트샵에서는 다음과 같은 주요 API 구조가 관찰되었다.

| API 경로                                             | 추정 용도          |
| -------------------------------------------------- | -------------- |
| `/api/v1.0/cnbUserData`                            | 공통 사용자 상태      |
| `/api/v1.0/user`                                   | 사용자 세션 확인      |
| `/api/v1.0/unifiedStore/my/auth`                   | 접근 또는 구매 가능 여부 |
| `/api/v1.0/unifiedStore/my/currency/purplepoint`   | 포인트 정보         |
| `/api/v1.0/unifiedStore/my/membership/purplepoint` | 멤버십 정보         |
| `/api/v1.0/unifiedStore/displayGoods/list`         | 공개 상품 목록       |

#### CORS 확인

퍼플 포인트 공개 상품 목록 요청을 정상 Origin과 외부 Origin으로 각각 1회 비교하였다.

| 조건                                 | 결과                                 |
| ---------------------------------- | ---------------------------------- |
| `Origin: https://store.plaync.com` | `HTTP 200`, 상품 1건 반환, 해당 Origin 허용 |
| `Origin: https://example.com`      | 비 200 응답, 상품 목록과 CORS 허용 헤더 미반환    |

외부 Origin의 반사 또는 임의 허용은 확인되지 않았다.

#### `cnbUserData` 미로그인 응답

Cookie 없이 응답 구조를 확인한 결과 `isLogin:false`, `guid:null`, `ncAccount:null`이 반환되었다. `gameAccount`의 캐릭터 관련 필드는 모두 빈 문자열이었고 이메일 형식 값이나 Bearer 토큰은 확인되지 않았다. 외부 Origin을 적용한 요청은 `403 Forbidden`으로 거부되었다.

#### 결과 및 한계

이번 점검에서는 미로그인 사용자 정보 노출, 외부 Origin 허용 또는 인증 우회가 확인되지 않았다. 로그인 계정 간 권한 비교, 상품 ID 변경, 비공개 상품 탐색, 결제·포인트·쿠폰 등 상태 변경 기능은 점검하지 않았다. 자동 스캔, 퍼징 및 무차별 대입도 수행하지 않았다.
