# [제 2차 프로젝트 진행 보고서] 하품 홈페이지 웹 서비스 보안 취약점 분석

- **팀원:** (팀장) 20245035_강준수, (팀원) 20245039_김레빈, 20251790_김준수, 20252751_김홍균
- **활동 기간:** 2026. 05. 13. ~ 2026. 05. 19. (1주)

## 팀 전체 진행 현황

- **이번 회차 목표:**
  운영 중인 `https://hapum.org/` 서비스에 영향을 주지 않는 범위에서 공개적으로 확인 가능한 보안 설정과 웹 응답을 우선 점검한다. 자동 취약점 스캔, 인증 우회, 파일 업로드 공격, 로그인·회원가입 대량 요청처럼 운영 영향 가능성이 있는 항목은 범위 승인 전까지 보류하고, HTTP 응답, 보안 헤더, 쿠키 속성, CORS 정책, 공개 HTML/JavaScript, 에러 응답을 중심으로 중간 점검 결과를 작성한다.

- **현재 진행률:** 30%
  1차 보고서에서 정리한 사전 점검 항목을 바탕으로 실제 대상 서비스의 공개 응답을 확인하는 단계까지 진행하였다. 아직 인증 후 기능, 권한 분리, 파일 업로드, 관리자 기능, DB 관련 PoC는 운영자 승인 범위가 확정되지 않아 수행하지 않았으므로, 본 회차 결과는 취약점 확정 보고서가 아니라 공개 설정과 취약 가능성 중심의 중간 진단 결과로 정리하였다.

- **주요 달성 사항:**
  - `hapum.org`의 HTTP/HTTPS 응답, 보안 헤더, 쿠키 속성, CORS 정책, 공개 HTML/JS, 에러 응답, `robots.txt`, `security.txt` 존재 여부를 점검하였다.
  - 운영 서비스에 직접적인 부담을 줄 수 있는 자동 스캔, 인증 우회, 파일 업로드 공격, 대량 요청, DB 관련 PoC는 수행하지 않고 보류 항목으로 분리하였다.
  - 높은 우선순위 조치 항목으로 CORS 과다 허용, 세션 쿠키 보안 속성 부족, CSRF 방어 미흡 의심을 정리하였다.
  - 중간 우선순위 항목으로 주요 보안 헤더 부족, 서버 및 스택 정보 노출, 입력 검증 및 예외 처리 미흡, HTTP 80 처리 불량, 공개 HTML/JS 정보 노출, 외부 스크립트 공급망 리스크를 정리하였다.
  - 낮은 우선순위 항목으로 `target="_blank"` 보호 미흡, `www.hapum.org` 미구성, `security.txt` 및 `robots.txt` 부재를 정리하였다.
  - Nginx와 Spring Boot 기준의 즉시 적용 가능한 개선안을 정리하였다.

## 이슈 및 해결 방안

- **문제 상황:**
  1. 대상 서비스가 운영 중인 웹 서비스이므로 자동 취약점 스캔, 로그인·회원가입 대량 요청, 파일 업로드 공격, 인증 우회 테스트는 서비스 장애나 데이터 훼손 가능성이 있다.
  2. 서버 사양이 디스크 30GB, 메모리 1GB 수준으로 낮은 것으로 파악되어 부하성 점검은 제한적으로 수행해야 한다.
  3. 현재 단계에서는 테스트 계정, 관리자 계정, 허용 IP, 점검 시간대, 자동 스캔 허용 여부, 파일 업로드 테스트 범위, DB 관련 검증 범위가 확정되지 않았다.
  4. CSRF, 인증 우회, 권한 상승, 데이터 접근 가능성은 실제 PoC까지 수행하지 않았으므로 취약점 확정이 아니라 취약 가능성 및 설정상 위험 요소로 구분해야 한다.

- **해결 현황:**
  운영 영향이 낮은 공개 응답 기반 점검만 먼저 수행하였다. 확인된 이슈는 위험도별로 분류하고, 즉시 개선 가능한 설정성 조치와 추가 승인이 필요한 심화 검증 항목을 분리하였다. 다음 회차에서는 운영자에게 테스트 계정, 관리자 계정 제공 여부, 허용 IP 및 점검 시간대, 자동 스캔 및 파일 업로드 테스트 허용 범위를 확인한 뒤 승인된 범위 안에서 인증·권한·XSS·파일 업로드·Rate Limit·관리자 API 접근제어를 점검할 예정이다.

## 다음 회차 목표

- 운영자에게 테스트 계정, 관리자 계정, 허용 IP, 점검 시간대, 자동 스캔 허용 여부를 확인한다.
- 인증 후 기능의 로그인, 세션 관리, 비밀번호 정책, 인증 실패 처리 방식을 점검한다.
- 일반 사용자와 관리자 기능 분리 여부 및 IDOR 가능성을 확인한다.
- 로그인, 회원가입, 대관 신청 등 상태 변경 요청에 CSRF 보호가 적용되어 있는지 검증한다.
- 입력값 반영 지점에서 XSS 가능성과 출력 인코딩 여부를 확인한다.
- 파일 업로드 기능이 있는 경우 확장자, MIME 타입, 저장 경로, 실행 가능성 검증을 수행한다.
- 로그인, 회원가입, 인증번호, 주요 POST 요청에 Rate Limit이 적용되어 있는지 확인한다.
- `/admin/*` 경로의 접근제어 및 직접 호출 가능성을 검증한다.
- Nginx와 Spring Boot 설정 개선안 적용 여부를 재확인하고, 보안 체크리스트를 갱신한다.
