# [제 1차 프로젝트 진행 보고서] 하품 홈페이지 웹 서비스 보안 취약점 분석

- **팀원:** (팀장) 20245035_강준수, (팀원) 20245039_김레빈, 20251790_김준수, 20252751_김홍균
- **활동 기간:** 2026. 04. 29. ~ 2026. 05. 05. (1주)

## 팀 전체 진행 현황

- **이번 회차 목표:** 
  프로젝트 계획서에서 설정한 웹 서비스 보안 취약점 분석 프로젝트를 실제로 수행하기 위해, 분석 범위와 테스트 절차를 구체화하고 웹/서버/인프라 영역별 사전 조사 및 환경 준비를 진행한다.

- **현재 진행률:** 10% 
  전체 프로젝트 기준으로 본격적인 취약점 검증 단계에 들어가기 전, 분석 대상과 방법론을 정리하는 초기 준비 단계이다.

- **주요 달성 사항:**  
  - 프로젝트의 분석 범위를 웹 취약점, 서버 환경, 인증/권한 관리, 운영 보안, 내부 시스템 접근 가능성으로 구분하였다.
  - 실제 서비스에 영향을 주지 않기 위해 허가된 테스트 범위와 테스트용 서버 필요성을 재확인하였다.
  - 웹 서비스 보안 수준을 높이기 위한 기본 점검 항목을 정리하였다.
    - 입력값 검증
    - 인증 및 세션 관리
    - 접근 제어
    - 파일 업로드
    - 서버 설정
    - 로그 및 모니터링
    - 권한 관리
  - 프로젝트 결과물을 단순 취약점 목록이 아니라, 위험도 평가와 대응 방안을 포함한 보안 체크리스트 형태로 정리하는 방향을 확정하였다.

## 이슈 및 해결 방안

- **문제 상황:** 
  1) 실제 웹 서비스 또는 이와 유사한 테스트용 서버를 대상으로 분석을 진행해야 하므로, 분석 권한과 테스트 범위를 명확히 하지 않으면 서비스 장애나 권한 문제가 발생할 수 있다. 
  2) 현재는 소스코드 및 서버 내부 접근 권한이 확정되지 않았다.

- **해결 현황:** 
  본 회차에서는 무리하게 실제 공격 테스트를 수행하기보다, 먼저 분석 범위와 절차를 정리하였다. 다음 회차부터는 허가된 범위 내에서 테스트 서버 또는 복제 환경을 기준으로 취약점 검증을 진행할 예정이다.
  우선 외부에서 확인 가능한 웹 서비스 기능 구조, 요청/응답 흐름, 인증/세션 처리 방식, 입력 지점 등을 중심으로 분석 범위를 정리한다. 이후 접근 권한이 확보되면 서버 설정, 배포 구조, 권한 관리, 로그 관리 등 내부 보안 점검으로 확장한다.

## 다음 회차 목표

- 테스트 대상 웹 서비스 또는 테스트용 서버 환경 구조 파악
- 웹 페이지 기능별 입력 지점 정리
- Burp Suite를 이용한 요청/응답 흐름 분석
- 로그인, 세션, 파일 업로드, 게시글/댓글 등 주요 기능별 보안 점검
- SQL Injection, XSS, 파일 업로드 취약점 등 기본 웹 취약점 1차 테스트
- 발견된 취약점 후보에 대해 위험도, 영향도, 대응 방안 정리
- 서버 설정, 접근 권한, 로그 관리 등 서버 운영 보안 점검 항목 구체화
