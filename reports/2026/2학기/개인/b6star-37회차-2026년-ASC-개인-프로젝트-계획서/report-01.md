## 프로젝트 개요

> LLM으로 취약 웹을 생성하고, AI Agent 기반 레드팀 도구로 취약점을 검증하는 보안 실습 시스템을 개발한다. 레드팀은 테스트 실행과 결과 수집·판정을 수행한다. DVWA와 다른 공개 실습용 서버에서 도구를 검증한 뒤 웹 생성 기능을 연결하고, 수집한 결과는 이후 별도로 분석하여 보고서로 작성한다.
> 

## 기대 효과

- 취약 웹 생성부터 검증·분석까지 이어지는 보안 실습 환경을 구축한다.
- 실제 테스트 결과를 바탕으로 웹 보안과 AI Agent 개발 역량을 기른다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진 배경 및 취지)

- 사용자가 원하는 취약점 유형과 난이도에 맞는 웹을 생성하고, 이를 검증할 수 있는 실습 환경을 마련한다.
- AI Agent가 웹의 특성에 맞춰 테스트를 수행하고 실제 요청·응답을 근거로 취약점을 판단하도록 한다.
- 공개 실습용 서버에서 레드팀의 검증 능력을 확인한 뒤 웹 생성 기능과 연결하여 전체 실습 흐름을 완성한다.

## 2. 프로젝트 세부내용

- **사전 점검:** Docker로 실행한 DVWA에 로컬 LLM과 MCP 도구를 연결하여 SQL Injection 테스트를 수행했다. 테스트 결과와 실제 응답을 확인함으로써 AI Agent가 도구를 활용해 취약점을 검증하고 레드팀 역할을 수행할 가능성을 기초 실습 수준에서 검증했다.
- **레드팀 도구 개발:** DVWA를 초기 검증 환경으로 활용하여, AI Agent가 대상 웹의 특성에 맞춰 테스트를 선택·실행하고 수집한 응답을 바탕으로 취약점 재현 여부를 판단하도록 구현한다. 재현된 취약점과 미확인 항목은 구분해 기록한다.
- **다른 실습용 서버 검증:** DVWA에서 구현한 도구를 다른 공개 실습용 서버에서도 시험한다. 로그인 방식과 웹 구조가 달라져도 테스트와 취약점 판정이 가능한지 확인하고, 필요한 기능과 서버별 설정을 보완한다.
- **실행 속도 개선 및 환경 비교:** 로컬 LLM의 긴 작업 시간을 개선하기 위해 컴퓨터 환경과 모델·설정을 바꾸어 실행 속도와 검증 결과를 비교한다. 모든 과정을 LLM에 맡기는 구조를 개선하는 방안으로 JEV 활용도 검토한다. 속도가 충분히 개선되지 않으면 DeepSeek API 방식으로의 전환도 고려한다.
- **취약 웹 생성 도구 개발:** 레드팀 도구의 기본 검증을 마친 뒤, 사용자가 입력한 취약점 유형과 난이도에 맞춰 LLM이 웹 코드를 생성하도록 구현한다. 생성한 웹의 정상 실행 여부와 의도한 취약점의 재현 가능성을 확인하여 실습 환경으로 활용할 수 있는지 검증한다.
- **통합 및 보고서 작성:** 생성한 웹을 Docker로 실행하고 레드팀 도구에 연결하여 웹 생성부터 취약점 검증까지의 흐름을 통합한다. 검증이 끝난 뒤 수집한 결과를 별도로 분석하고, 취약점의 근거·원인·방어 방법을 보고서로 정리한다. 별도의 블루팀과 자동 패치 기능은 개발 범위에서 제외한다.

## 3. 프로젝트 기대효과

- 다양한 취약점 유형과 난이도를 다룰 수 있는 반복 가능한 웹 보안 실습 환경을 확보한다.
- 실제 응답과 재현 결과를 근거로 AI Agent의 판단을 평가하며 취약점 분석·검증 능력을 높인다.
- 서로 다른 서버와 모델에서 도구를 시험하며 범용적인 AI Agent 설계 경험을 쌓는다.

## 4. 프로젝트 수행 시 예상 문제점

- **실행 시간:** 로컬 모델의 크기, 컴퓨터 사양, 입력 길이와 도구 호출 횟수에 따라 작업 시간이 길어질 수 있다. 환경·모델 비교와 JEV 활용을 통해 개선하고, 충분한 개선이 어려우면 DeepSeek API 방식으로 전환한다.
- **도구 호출 및 상태 관리:** 잘못된 호출 인자나 로그인·세션 처리 오류로 테스트가 중단되거나 결과가 왜곡될 수 있다. 반복되는 절차는 실행 코드에서 처리하고, 오류 처리와 종료 조건을 마련한다.
- **모델·서비스의 작업 제한:** Codex를 활용한 사전 시도에서는 사이버보안 관련 제한으로 진행이 차단됐다. 사용할 모델이나 API가 필요한 보안 실습 작업을 수행할 수 있는지 사전에 확인한다.
- **생성 코드의 품질:** 생성한 웹이 실행되지 않거나 의도한 기능·취약점을 포함하지 않을 수 있다. 정상 동작과 취약점 재현 여부를 각각 확인한다.

## 5. 프로젝트 수행 시 요구사항

- **필요 지식:** Python, HTTP 요청·응답, 쿠키·세션과 로그인 처리, 웹 취약점 전반의 원리, Docker, LLM 도구 호출 및 MCP에 대한 이해.
- **개발 환경:** 개발용 PC 또는 노트북에 Docker, Python, Git, LM Studio와 로컬 모델을 구성한다. 실행 속도 개선을 위해 JEV 활용을 검토하고, 필요 시 DeepSeek API를 연결할 수 있도록 설계한다.
- **완료 기준:** 사용자가 입력한 취약점 유형과 난이도에 맞는 웹을 생성·실행하고, 레드팀 도구가 해당 웹의 취약점을 테스트하여 결과를 수집·판정하는 전체 흐름이 동작해야 한다. 검증 이후에는 재현 결과와 미확인 항목을 구분하고, 취약점의 근거·원인·방어 방법을 정리한 분석 보고서와 실행 안내를 작성한다.

## 개인 수행 계획

- **수행 순서:** 레드팀 도구 개발 → DVWA 및 다른 공개 실습용 서버에서 검증 → 취약 웹 생성 도구 개발 → 전체 흐름 통합 → 결과 분석 및 보고서 작성. 실행 환경 비교와 속도 개선은 레드팀 개발 과정에서 함께 진행한다.
- **예상 산출물:** 레드팀 및 취약 웹 생성 도구 코드, 서버별 설정, 테스트 요청·응답과 판정 기록, 실행 환경별 성능 비교 자료, 후속 분석 보고서, 실행·테스트 안내.
- **검증 방법:** 동일한 서버 상태와 테스트 목표로 반복 실행하여 재현 결과, 오탐 여부, 실행 시간과 도구 호출 오류를 비교한다. API 사용 시 사용량과 비용을 기록하고, 생성한 웹은 정상 동작과 의도한 취약점의 재현 여부를 각각 확인한다.
