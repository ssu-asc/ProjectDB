# [제 1차 개인 프로젝트 진행 보고서] ASC 개인 프로젝트 1회차

- **작성자:** 이지원 (team04_03)
- **활동 기간:** 2026. 10. 26. ~ 2026. 11. 01.

## 프로젝트 진행 현황

- **이번 회차 목표:** 드림핵 시스템 해킹 자료를 활용하여 Linux 메모리 구조와 함수 호출 원리를 학습하고, 메모리 오류가 공격으로 이어지는 조건을 분석하기 위한 기초 지식을 정리한다.
- **현재 진행률:** 약 15% (전체 일정 대비 추정)
- **주요 달성 사항:** 메모리 영역별 역할과 접근 권한, 스택의 동작 방식, 함수 호출과 반환 과정을 정리하였다. pwntools의 기본 입출력 함수와 로컬 실행·원격 연결 방식의 차이를 학습하였다.

## 수행 내역

- **수행 작업:** 기존에 학습한 드림핵 내용을 바탕으로 코드·데이터·BSS·힙·스택 영역의 특징을 정리하고, 예제 코드의 변수와 데이터가 배치되는 위치를 구분하였다. 스택이 낮은 주소 방향으로 확장되는 원리와 push, pop, call, ret의 역할을 정리하였다. 또한 pwntools의 process(), remote(), sendline(), recvuntil() 사용법과 문자열·바이트 자료형 및 패킹·언패킹의 차이를 정리하였다.
- **산출물 링크:** 별도 링크 미첨부. 개인 학습 노트에 메모리 구조, 스택 동작 및 pwntools 핵심 내용을 정리하였다.
- **검증/확인 내용:** 예제 코드를 통해 포인터 변수 자체의 저장 위치와 포인터가 가리키는 영역이 다를 수 있음을 확인하였다. 스택의 확장 방향과 일반적인 데이터 저장 순서를 구분하고, call이 반환 주소를 저장하며 ret이 이를 이용해 실행 흐름을 복구한다는 점을 정리하였다. 로컬 프로그램 실행과 원격 서버 연결에 사용하는 pwntools 함수의 차이도 확인하였다.

## 이슈 및 해결 방안

- **문제 상황:** 스택의 확장 방향과 데이터 저장 순서를 혼동하여 메모리 구조도를 해석하는 데 어려움이 있었다. 함수 호출 과정에서 call, pop, ret의 역할을 구분하는 데 추가 학습이 필요하였다. 기존 pwntools 실습에서는 Windows의 WSL 접근 경로와 Linux 내부 경로를 혼동하여 Python 문자열 오류가 발생하였다.
- **해결 현황:** 주소 값과 스택 포인터의 변화를 단계별로 비교하여 스택 동작에 대한 이해를 보완하였다. 각 명령어를 반환 주소 저장, 데이터 인출, 실행 흐름 복구로 구분하여 정리하였다. 경로 오류는 Linux 내부 경로와 process()를 사용하는 방식으로 수정 방향을 확인하였으며, 실행 결과 재확인은 다음 실습에서 진행할 예정이다.

- 소스코드와 어셈블리를 비교하여 지역 변수, 스택 프레임, 반환 주소의 관계를 정리한다.
- 스택 버퍼 오버플로 예제를 구성하고 입력 길이에 따른 실행 결과를 기록한다.

- 실험 환경, 컴파일 옵션, 입력값, 관찰 결과를 정리하여 분석 보고서의 기초 자료를 마련한다.
