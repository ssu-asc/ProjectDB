## 프로젝트 개요

> 검증된 3가지 CTF 에이전트를 구축하고 동일한 자원(모델,문제,시간 등)에서의 해결률, 풀이 시간, 토큰 소모량, 접근 방식 등을 비교 분석한다. 분석으로 검증된 장점을 이전에 팀이 개발 중인 CTF 에이전트에 적용하여 확장한다.

# 프로젝트 세부 계획서

## 1. 프로젝트 목적 (추진배경, 취지 등)

- 이전에 CTF 에이전트를 구축하던 작업을 하던중 어떻게 문제에 접근해야하는지, 어떤 방법을 써야 성능이 잘 나오는지에 대한 호기심이 가득했던 상태였음.
- 이미 검증된 CTF 에이전트들은 어떤 방식으로 어떻게 구축해놨는지, 성능은 얼마나 나오는지 등 비교 분석하고픈 마음이 있었음.

## 2. 프로젝트 세부내용

- 설계 축이 다른 3종의 에이전트를 같은 조건에서 돌려 비교하고 분석한다. 효과가 확인된 요소를 자체 에이전트에 이식한다.
- NYU baselin(단일 에이전트,대조군) / EniGMA(도구 강화 에이전트) / D-CIPHER(멀티 에이전트) 들을 동일조건에서 같은 모델, 20~30문제 정도 반복 실행 등해서 비교 분석을 한다(지표나 실패 유형 비교 / 해결률, 풀이시간, 접근 방식, 비용 등), 후에 팀이 만들던 에이전트에 확장시키는 목표

## 3. 프로젝트 기대효과

- 도구나 역할을 분담한 에이전트들이 각각 어떤 문제 유형에서 효과가 있는지 알아볼 수 있음
- 비교 결과를 반영한 자체 에이전트를 ctf 풀이 도우미나 대회에서도 활용 가능

## 4. 프로젝트 수행시 문제점 (내외부 요인 기술)

- 에이전트마다 프롬프트, 도구, 환경이 달라 모델 외에는 조건을 완전히 맞추기가 어려워 완벽한 결과가 아님
- 모델 내부 추론은 확인할 수 없어서 토큰 소모의 원인은 분석 X
- API 비용 부담

## 5. 프로젝트 수행시 요구사항 (프로젝트 구성원, 개발환경 등)

- 평가 문제셋:  NYU CTF Bench + 최근 대회 또는 자체 제작 문제
-LLM API 키와 에산
