## 이번 회차 세부 진행 내용

### 1. 인증 영역(A-1) - 비밀번호 재설정 기능 분석

`id.plaync.com`의 비밀번호 재설정 기능을 대상으로 Burp Suite를 이용한 수동 점검을 수행하였다.

#### 테스트 절차

1. 비밀번호 재설정 페이지에서 테스트 계정 이메일 입력
2. 이메일로 수신한 인증번호를 입력하여 본인 인증 수행
3. 비밀번호 재설정 화면 진입
4. Burp Suite를 이용하여 비밀번호 변경 요청 캡처
5. 요청 구조 및 서버 검증 방식 분석
6. Burp Repeater를 이용한 재전송 테스트 수행

---

### 2. 비밀번호 재설정 요청 분석

비밀번호 변경 요청에 다음 정보가 포함되는 것을 확인하였다.

- `newPassword`
- `findPasswordTokenId`
- `verifiedCaptchaKey`

비밀번호 재설정 과정에서는 이메일 인증 과정에서 발급된 토큰과 CAPTCHA 검증 결과를 서버에서 함께 검증하는 것으로 확인되었다.

---

### 3. 서버 측 검증 확인

#### (1) 기존 비밀번호 검증

로그인 상태의 비밀번호 변경 기능에서 기존 비밀번호 값을 임의로 변경한 뒤 요청을 전송하였다.

**결과**

```text
입력하신 정보가 정확하지 않습니다. 다시 입력해 주세요.
```

서버에서 기존 비밀번호의 일치 여부를 검증하고 있음을 확인하였다.

#### (2) 새 비밀번호 정책 검증

Burp Suite를 이용하여 비밀번호 정책을 만족하지 않는 새 비밀번호를 서버로 직접 전송하였다.

**결과**

- 비밀번호 정책을 만족하지 않는 값을 전송하였을 때 HTTP 응답을 확인하지 못하였다.
- 비밀번호 변경은 수행되지 않았다.

응답을 확인하지 못한 원인은 이번 테스트만으로 특정할 수 없었다. 다만 정책에 맞지 않는 비밀번호로 변경되지 않은 것은 확인하였다.

---

### 4. 이메일 인증 토큰 재사용 여부 확인

비밀번호 재설정을 정상적으로 완료한 뒤 약 3분 이내에 동일한 `findPasswordTokenId`를 포함한 요청을 Burp Repeater로 다시 전송하였다.

**응답**

```json
{
  "code": "A9900000009",
  "message": "error:3301, product:1186, module:4, line:3685, text:verifiedEmailTokenId is invalid or expired, statusCode:null, restData:{}"
}
```

#### 분석

서버는 이메일 인증 토큰(`verifiedEmailTokenId`)의 유효성을 검증하고 있었으며, 동일한 토큰을 이용한 재전송 요청을 허용하지 않았다.

재전송을 비밀번호 재설정 완료 직후에 수행했으므로, 단순 시간 만료보다는 비밀번호 재설정 완료와 함께 토큰이 무효화되었을 가능성이 높다고 판단하였다. 다만 응답 메시지가 `invalid or expired`로 두 원인을 구분하지 않으므로 토큰이 사용 즉시 폐기되었다고 단정할 수는 없다. 현재 확인된 방어 동작과 테스트 범위를 고려하여 이를 구분하기 위한 추가 테스트는 수행하지 않았다.

---

| 점검 항목        | 결과                                                     |
| ------------ | ------------------------------------------------------ |
| 기존 비밀번호 검증   | 서버에서 정상적으로 검증 수행                                       |
| 새 비밀번호 정책    | 정책 미준수 입력 시 HTTP 응답을 확인하지 못했으며, 비밀번호 변경은 수행되지 않음       |
| 이메일 인증 토큰 검증 | 서버에서 토큰 유효성 검증 수행                                      |

### 결론

비밀번호 재설정 기능을 수동 점검한 결과, 서버가 기존 비밀번호, 새 비밀번호 정책 및 이메일 인증 토큰에 대해 서버 측 검증을 수행하는 것을 확인하였다. 비밀번호 재설정 완료 후 동일한 토큰을 이용한 재전송은 허용되지 않았으며, 서버는 토큰이 유효하지 않거나 만료되었다는 오류를 반환하였다. 이번 점검에서는 서버 측 검증이 정상적으로 동작하는 것을 확인하였고, 비밀번호 재설정 기능과 관련된 취약점은 발견하지 못하였다.

### 5. API 기초 영역(B-1~B-3) - Store API Recon

`store.plaync.com` 및 `store-bff.plaync.com`을 대상으로 Burp Suite를 이용해 API 요청 구조를 확인하였다.

점검 범위는 사용자가 정상적으로 접근할 수 있는 Store 화면에서 발생한 요청 수집과 분석으로 제한하였다.

#### 테스트 절차

1. OpenVPN 및 Burp Suite 프록시 연결 상태 확인
2. `https://store.plaync.com` 접속 후 `store.plaync.com/store/lin` 이동 확인
3. 페이지 로딩 과정에서 발생하는 `store-bff.plaync.com` 요청 확인
4. 공개 Store 화면에서 `월간 패스`, `아이템`, `부가서비스` 카테고리 클릭
5. 추가로 `에피소드 특전`, `주간 패스` 카테고리 클릭
6. 공개 상품 1개 상세 페이지 진입
7. Burp HTTP History 및 Export 파일 기반 요청/응답 구조 분석

---

### 6. Store API 요청 분석

Store 페이지 진입, 카테고리 전환, 상품 상세 진입 과정에서 다음 `store-bff.plaync.com` 요청이 확인되었다.

| API 경로                                     | 용도 추정              | 관찰 결과                          |
| ------------------------------------------ | ------------------ | ------------------------------ |
| `/api/v1.0/user`                           | 사용자 세션 확인          | 미로그인 상태에서 `Session Expired` 반환 |
| `/api/v1.0/unifiedStore/my/currency/lin`   | 보유 재화 또는 통화성 정보 확인 | 미로그인 상태에서 `Session Expired` 반환 |
| `/api/v1.0/unifiedStore/my/lin`            | 사용자별 상점 상태 확인      | 미로그인 상태에서 `Session Expired` 반환 |
| `/api/v1.0/unifiedStore/my/auth`           | 구매 또는 접근 가능 여부 확인  | 미로그인 상태에서 `Session Expired` 반환 |
| `/api/v1.0/unifiedStore/my/membership/lin` | 멤버십 상태 확인          | 미로그인 상태에서 `Session Expired` 반환 |
| `/api/v1.0/unifiedStore/displayGoods/list` | 카테고리별 상품 목록 조회     | 카테고리 조건에 따라 상품 목록 JSON 반환      |
| `/api/v1.0/unifiedStore/preferenceGoods`   | 관심 상품 관련 정보 조회     | 미로그인 상태에서 `Session Expired` 반환 |

확인된 요청은 모두 `GET` 방식이며, 응답의 `Content-Type`은 `application/json`이었다.

요청에는 `Cookie` 헤더가 포함되어 있었으나 `Authorization` 헤더는 확인되지 않았다. Cookie 및 세션 관련 값은 민감정보로 판단하여 원문을 기록하지 않았다.

---

### 7. 미로그인 상태 응답 확인

사용자별 정보로 보이는 API는 HTTP 상태 코드로는 `200`을 반환했지만, 응답 본문에서는 세션 만료 상태를 나타냈다.

**응답 예시**

```json
{
  "data": null,
  "status": 401,
  "errorCode": "401",
  "message": "Session Expired"
}
```

#### 분석

서버는 미로그인 상태에서 사용자 정보를 반환하지 않고 세션 만료 응답을 반환하였다.

인증 실패를 HTTP `401`이 아니라 HTTP `200` 응답 안의 JSON 본문으로 표현하고 있어, 클라이언트는 응답 본문의 `status` 또는 `errorCode` 값을 기준으로 세션 상태를 판단하는 것으로 보인다.

이번 범위에서는 Cookie 제거, 세션 변조, 다른 계정 정보 접근 시도는 수행하지 않았다.

### 8. 공개 상품 목록 API 확인

Store 메인 페이지 및 카테고리 전환 과정에서 `/api/v1.0/unifiedStore/displayGoods/list`가 호출되는 것을 확인하였다.

해당 API는 `categoryKey`, `channelType`, `pageIndex`, `pageSize`, `orderType`, `shopCode`, `languageCode` 값을 기준으로 상품 목록을 조회하는 구조로 보인다.

| UI 동작             | 주요 요청 조건                                           | 관찰 결과                                       |
| ----------------- | -------------------------------------------------- | ------------------------------------------- |
| `월간 패스` 카테고리 클릭   | `categoryKey` 포함                                   | 상품 목록 API 재호출 확인                            |
| `아이템` 카테고리 클릭     | `categoryKey`, `subCategoryId` 포함                  | 상품 목록 API 재호출 확인                            |
| `부가서비스` 카테고리 클릭   | `categoryKey` 포함                                   | 상품 목록 API 재호출 확인                            |
| `에피소드 특전` 카테고리 클릭 | `categoryKey=68E23B01-2690-4D16-946C-E0BE6D1B4E15` | `totalCount: 15`, `displayGoodsList` 15건 반환 |
| `주간 패스` 카테고리 클릭   | `categoryKey=NORMAL-WEEKLY`                        | `totalCount: 0`, `displayGoodsList` 빈 배열 반환 |

`주간 패스` 화면에서는 상품 목록 API가 정상 응답을 반환했으나, 응답 데이터가 비어 있어 화면에는 `진열된 아이템이 없습니다.`가 표시되었다.

### 9. 상품 상세 진입 확인

공개 상품 목록에서 `정복자의 스페셜 출석 패스 상자` 상품 상세 페이지에 1회 진입하였다.

| 항목         | 내용                                                      |
| ---------- | ------------------------------------------------------- |
| 상품명        | `정복자의 스페셜 출석 패스 상자`                                     |
| 상세 URL     | `/store/lin/goods/028E90AC-6470-F111-A2F4-00155D204308` |
| 화면상 확인된 버튼 | `장바구니 담기`, `구매`, `퍼플앱으로 구매`                             |

상품 상세 진입 직후 `store-bff.plaync.com`에서 `/api/v1.0/unifiedStore/preferenceGoods` 요청이 추가로 확인되었다. 해당 요청은 미로그인 상태에서 `Session Expired`를 반환하였다.

이번 Export 범위에서는 상품 상세 URL의 UUID를 포함한 별도 `store-bff.plaync.com` 상세 조회 API는 확인하지 못하였다. 상품 상세 본문은 `store.plaync.com` 화면에서 정상 표시되었고, 추가 조작 없이 상세 화면 구조만 확인하였다.

| 상품 상세 진입     | 공개 상품 1건 상세 페이지 진입 확인                         |
| 관심 상품 API    | 미로그인 상태에서 `Session Expired` 반환                |
| 인증 헤더 확인     | `Authorization` 헤더는 확인되지 않음                   |
| Cookie 헤더 확인 | Cookie 헤더 포함 확인, 원문은 기록하지 않음                  |
| 취약점 발견 여부    | 발견하지 못함                                       |

### 결론

Store API Recon 결과, `store.plaync.com`의 공개 Store 화면은 `store-bff.plaync.com`을 통해 사용자 상태, 상품 목록, 관심 상품 관련 정보를 조회하는 구조로 확인되었다.

미로그인 상태에서 `/user`, `/my/*`, `/preferenceGoods` 계열 요청은 실제 사용자 데이터를 반환하지 않고 `Session Expired` 응답을 반환하였다. `/displayGoods/list`는 공개 상품 목록 조회 기능으로 동작하며, 카테고리 조건에 따라 상품 목록 또는 빈 목록을 반환하였다.

상품 상세 URL에는 공개 상품 UUID가 포함되었고, 화면에는 구매 관련 버튼이 표시되었다. 이번 점검은 정상 UI 탐색 중 발생한 요청을 대상으로 하였으며, 장바구니, 구매, 로그인, 요청 재전송, 파라미터 변조 등 상태 변경 가능성이 있거나 권한 검증이 필요한 동작은 범위에서 제외하였다.

현재 범위에서는 API 기초 영역과 관련된 취약점은 발견하지 못하였다.
